- 目标应用：寰球云联自动化平台（`hqyl_desktop`）

## 2. 业务目标

在桌面端新增“Lazada 提现统计”流程。用户选择国家、填写店铺名称并确认统计日期后，程序通过紫鸟浏览器进入对应 Lazada Seller Center：

- 菲律宾、马来：筛选并抓取全部提现流水，生成结构化 Excel。
- 泰国：下载匹配统计日期的收入账单 `Order Details` 文件。
- 所有成功产物按统一目录规则上传到指定钉盘。
- 桌面端实时展示店铺级进度、成功/失败状态、本地文件和钉盘路径。

本流程只归档提现明细，不计算或汇总提现金额，不写入钉钉在线表格。

## 3. 已确认需求

### 3.1 支持国家

| 国家 | 代码 | 用户输入 | 业务产物 |
|---|---|---|---|
| 菲律宾 | `PH` | 选择国家后填写店铺名称 | 每店铺一个提现流水 Excel |
| 马来西亚 | `MY` | 选择国家后填写店铺名称 | 每店铺一个提现流水 Excel |
| 泰国 | `TH` | 选择国家后填写店铺名称 | 日期范围内匹配账期的一个或多个账单文件 |

一次任务只选择一个国家。店铺名称一行一个，不再依赖旧的“LZ跨境店铺余额提现统计”在线表格。

### 3.2 日期规则

- 默认开始日期：上一个自然月 1 日。
- 默认结束日期：上一个自然月最后一天。
- 例如应用日期为 `2026-07-15`，默认统计期为 `2026-06-01 ～ 2026-06-30`。
- 用户可以修改日期。
- 首版要求开始、结束日期属于同一个自然月，避免钉盘月份归档歧义。
- 归档月份取开始日期月份，例如 `2026-06-01` 对应 `6月`。
- 开始日期不得晚于结束日期，结束日期不得晚于当天。

### 3.3 菲律宾、马来页面流程

1. 根据国家和店铺名称匹配紫鸟 Lazada 店铺。
2. 启动店铺浏览器并确认 Lazada 已登录。
3. 进入“财务 / Finance”。
4. 进入“我的余额 / My Balance”。
5. 滚动到“余额流水 / Balance Transactions”。
6. 点击并严格校验“提现 / Withdrawal”已选中。
7. 设置开始日期和结束日期。
8. 严格校验页面显示的日期与用户输入一致，并确认日期弹层已经提交、关闭。
9. 等待流水表格加载完成；有记录和无记录都允许生成 Excel。
10. 逐页读取统计日期范围内的全部流水，不只读取第一屏；翻页时需防止重复行和死循环。
11. 页面字段映射：
    - `交易时间`：页面“交易时间 / Transaction Time”；
    - `类型`：页面“类型 / Type”，保留页面显示值；
    - `金额`：页面“金额 / Amount”，写为可计算的数值，保留正负号和小数；
    - `备注`：页面“备注 / Remarks”，保留完整多行文本；
    - `国家`：填写当前任务国家中文名；
    - `店铺`：填写当前紫鸟实际店铺名称。
12. Excel 表头顺序必须严格为：`交易时间、类型、金额、备注、国家、店铺`。
13. 每店铺生成 `{店铺名称}-withdrawal.xlsx`，校验文件可打开、表头和数据行数正确后上传钉盘。

“提现”筛选、日期范围、表格字段映射或翻页完整性任一项未校验成功时，流程必须停止，不能上传成功文件。

### 3.4 泰国页面流程

1. 根据国家和店铺名称匹配紫鸟 Lazada 泰国店铺。
2. 启动店铺浏览器并确认 Lazada 已登录。
3. 进入“财务 → 我的收入 / My Income”。
4. 切换到“收入账单 / Income Statement”。
5. 读取账单编号和账期，选择与统计日期范围有交集的账单。
6. 对每条匹配账单执行“下载 → Order Details (Excel)”。
7. 等待平台导出完成并下载文件。
8. 文件落地后校验：文件存在、大小大于 0、扩展名为 `.xlsx` 或平台实际返回的 `.csv`。
9. 使用 Lazada 原始账单编号和账期生成稳定文件名。
10. 上传钉盘；单个账单失败不阻塞同店铺其他账单，但店铺最终状态为“部分成功”。

若统计范围内没有匹配账单，店铺状态为“无匹配账单”，不记作上传成功。

## 4. 钉盘归档规则

### 4.1 固定位置

- 钉盘空间 ID：`28932857521`
- 提现统计根目录：`228929324648`
- 菲律宾目录：`228929555721`（`提现统计/lazada菲律宾`）

- 泰国目录：`228929395164`（`提现统计/lazada泰国`）

### 4.2 目录结构

```text
提现统计
├─ lazada菲律宾
│  └─ {M}月
│     └─ {店铺名称}
│        └─ {店铺名称}-withdrawal.xlsx
├─ lazada马来
│  └─ {M}月
│     └─ {店铺名称}
│        └─ {店铺名称}-withdrawal.xlsx
└─ lazada泰国
   └─ {M}月
      └─ {店铺名称}
         └─ {账单编号}_{开始日期}_{结束日期}_Order_Details.{xlsx|csv}
```

该结构与现有“余额统计”的“平台国家 → 月份 → 店铺 → 文件”规则一致。

### 4.3 文件命名与幂等

- 菲律宾、马来 Excel 名固定为 `{店铺名称}-withdrawal.xlsx`。
- 同一店铺同一月份重跑时覆盖同名 Excel；不再生成或上传旧版 PNG。
- 泰国文件保留稳定的账单编号和账期，例如：
  `TH1K15Y9ZZ-2026-023_20260601_20260607_Order_Details.xlsx`。
- Lazada 对同一 `Order Details (excel)` 入口可能按账单返回 `.xlsx` 或 `.csv`；稳定文件名保留平台实际扩展名，两种格式都必须读取内部账单号和账期后才能上传。
- 文件名需清理钉盘不支持的字符，但不得改变可识别的店铺主体。
- 同目录、同名文件重复运行时执行覆盖，避免自动生成重复副本。
- 覆盖只作用于本流程生成的确定性同名文件，不删除其他文件。

## 6. 状态与成功判定

| 状态 | 含义 |
|---|---|
| `success` | 所需页面步骤、产物生成和全部上传均成功 |
| `partial_success` | 泰国多个账单中仅部分下载或上传成功 |
| `no_data` | PH/MY 日期范围无流水，但仅含标准表头的 Excel 已生成并上传 |
| `no_matching_statement` | 泰国日期范围内没有匹配账单 |
| `page_unavailable` | Lazada 尚未向该店铺开放 My Balance |
| `need_manual_review` | 页面结构变化，筛选或日期无法可靠校验 |
| `failed` | 登录、页面跳转、截图/下载或上传失败 |
| `unmatched_store` | 输入店铺无法唯一匹配紫鸟浏览器 |

菲律宾、马来的 `no_data` 属于有效业务结果，但需要空数据 Excel 的表头校验及上传成功；任务汇总中单独统计。

菲律宾另测 `LZ跨境菲律宾墨硯003`，该店进入 `/apps/balance/unaccessable`，页面提示 My Balance 仍处试点阶段。生产实现必须把这种情况记录为 `page_unavailable`，不可误报成功或生成无效截图。

菲律宾、马来页面还有以下实测差异：

- 首次进入可能出现 `SELLER BALANCE UPDATED` 弹窗，需先关闭再操作。
- 页面语言可能是中文或英文，因此提现筛选需同时支持 `提现` 和 `Withdrawal`。
- 提现选中态可由按钮 class 中的 `next-btn-primary` 校验，未选中通常为 `next-btn-normal`。
- 日期必须在提交后从页面控件回读并与请求值逐日比对。
- 流水表按语义表头映射，不依赖列的中文或英文显示；备注读取单元格 `innerText`，保留单元格内换行。

泰国导出探查实际发现：导出弹窗会保留历史记录。点击“第一条已完成”的旧逻辑会下载错误账单，本轮已复现一次：页面请求 `TH1K0MVRAO-2026-027`，却下载到内部账单号 `TH1K0MVRAO-2026-023`。正确流程确定为：

1. 触发目标账单的 `Order Details` 导出。
2. 读取本次新增的顶部导出 ID。
3. 只轮询该 ID 对应行，由 `Processing` 等待到 `Finished`。
4. 只点击同一 ID 行的下载链接。
5. 下载后读取 Excel/CSV 首个数据行，校验内部账单号和账期与页面目标一致；不一致则拒绝上传。

修正后的实测导出 ID 为 `18708755`，平台文件名为 `TH1K0MVRAO-STATEMENT-18708755-20260715.xlsx`；保存后的稳定文件名为 `TH1K0MVRAO-2026-027_20260629_20260705_Order_Details.xlsx`，大小 `49,485` 字节。Excel 工作表 `Income Overview` 共 513 行，首个数据行的账单号为 `TH1K0MVRAO-2026-027`、账期为 `29 Jun 2026 - 05 Jul 2026`，验证通过。

正式端到端测试又确认：同一入口对部分账期返回 `.csv`。因此生产校验同时支持 `.xlsx` 与 `.csv`，但不会仅凭扩展名放行；文件内部账单号、账期仍必须与页面目标完全一致。

### 7.6 菲律宾、马来 Excel 需求二次探查（2026-07-16）

因菲律宾、马来产物由截图改为结构化 Excel，正式修改业务代码前重新用实际店铺串行探查，统计期仍为 `2026-06-01 ～ 2026-06-30`。本轮只导航、筛选和读取 DOM，不上传文件。

| 国家 | 实测店铺 | 行数 | 表头与数据证据 | 分页证据 |
|---|---|---:|---|---|
| 菲律宾 | `LZ跨境廣承主` | 5 | 英文表头依次为 `Transaction Number / Transaction Time / Type / Sub Type / Amount / Remarks`；金额包含千分位负数，如 `-7,850.47`；备注为 3 段多行文本 | `.next-pagination-item.next-prev/.next-next` 可稳定定位；本月前后页均为禁用 |
| 马来西亚 | `LZ跨境廣承主` | 1 | 同样为 6 个源列；示例金额 `-36.21`；备注中的银行流水号、到账说明和汇率文本均可从同一单元格完整取得 | 同一分页结构；本月前后页均为禁用 |

源表到结果表的实测映射确定为：

| 源表列 | Excel 列 | 处理 |
|---|---|---|
| `Transaction Time` / `交易时间` | `交易时间` | 解析为 Excel 日期时间值，显示到秒 |
| `Type` / `类型` | `类型` | 保留页面显示文本 |
| `Amount` / `金额` | `金额` | 去除千分位后写入数值，负号与小数保留 |
| `Remarks` / `备注` | `备注` | 保留单元格内换行并自动换行显示 |
| 无源列 | `国家` | 写入所选国家中文名 |
| 无源列 | `店铺` | 写入实际打开的紫鸟店铺名 |

`Transaction Number / 流水编号` 仅作为跨页去重键，不写入结果；`Sub Type / 子类型` 不写入结果。下一页按钮可用时，点击后必须等待当前页首笔流水编号变化；以“下一页禁用”作为正常结束条件，并设置最大页数及重复页保护。

据此，菲律宾、马来已满足新的表格提取开发闸门；泰国沿用 2026-07-15 已验证的下载方案，可以进入正式业务代码开发。
