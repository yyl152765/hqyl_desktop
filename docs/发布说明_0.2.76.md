# 0.2.76 发布说明

日期：2026-10-19。

修复 0.2.75 Lazada 提现统计在另一台电脑采集成功后，因钉盘配置缺失而全部上传失败的问题。

## 原因与修复

- 用户提供的 88 店日志中，80 店的 Excel 已通过校验，随后统一因钉盘配置缺失失败；7 店进入收入账单流程但没有匹配账单，1 店登录失败。
- 0.2.75 清理了冻结模块中的旧内置钉钉凭据，但提现入口未接入应用已经保存的钉钉设置。0.2.76 从本地设置注入 AppKey、AppSecret 和所选操作人的用户 ID，不再依赖发布包内的旧凭据。
- 提现页面增加钉钉操作人选择及配置状态。只有一位操作人时自动选择，多位时显式选择；缺少配置或选择时在任务启动前提示，不再逐店运行后才发现配置缺失。
- 服务入口同样先检查配置，再打开店铺。任务对象不在字符串表示中输出紫鸟密码或钉钉凭据。
- 受限店铺继续使用本国家的收入账单流程。每页日志增加账单数、匹配数及账期覆盖，区分整表明确无数据与已有账单但日期无匹配，并保存独立的收入页截图和脱敏 URL。

## 使用

更新后进入“Lazada 提现统计”，选择拥有目标钉盘目录权限的钉钉操作人。应用提示缺少配置时，在“设置 → 钉钉配置”中保存应用和操作人，再启动任务。升级保留用户现有设置；安装包不包含用户的应用密钥。

旧任务已生成的 Excel 保留在原任务输出目录，本次更新不会删除这些文件。

## 验证与限制

- 使用本机已保存的应用配置和之前的操作人绑定，真实获取访问令牌、解析操作人身份并只读列出马来钉盘根目录成功；没有写入钉盘或打开店铺。证据：`acceptance_outputs/lazada_drive_configuration_20261019/readonly_drive_check.json`。
- 回归覆盖空旧常量环境下的本地设置注入、操作人选择、缺项启动前拒绝、前端交互及服务预检；上传链路的离线集成保留真实 DriveClient 和文件校验，仅隔离远程边界。
- 此次真实在线验证为认证和目录读取，没有执行生产文件上传；不能据此声称另一台电脑的设置与权限已验收。
- 用户新日志中 7 家受限店铺没有发生下载。此次实店复核「諾鋒013」「廣承011」，恢复已有登录后，两次观察均明确显示收入账单 `No Data`、0 行、无加载状态、翻页禁用，确认这两店当前整表为空；其余五店未重新核查，不扩大结论。本版新增诊断证据，未将没有匹配账单改报成功。之前泰国实店下载仍受登录失效影响，未将其计为下载验收通过。证据：`acceptance_outputs/lazada_income_recheck_20261019/result.json`。
- 安装器与主程序仍未数字签名。另一台电脑的 Windows 应用控制拦截问题需受信任签名或组织策略处理，本次钉盘修复不改变系统安全策略。
