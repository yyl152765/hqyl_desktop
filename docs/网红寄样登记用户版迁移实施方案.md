# 网红寄样登记用户版迁移实施方案

> 本文档用于指导 Claude 在 `D:\hqyl_project\hqyl_desktop` 中完成“网红寄样登记用户版”迁移。请按本文档直接实施、测试和交付，不要只生成示例代码或停留在方案阶段。

## 1. 目标

把以下现有用户版能力迁入寰球云联桌面端：

- 马帮账号登录。
- 用户维护登记表格 ID。
- 用户维护组长、目标 Sheet、输出文件名和店铺列表。
- 支持昨天、指定日期、日期范围三种运行方式。
- 运行前校验用户填写店铺与马帮店铺的匹配关系。
- 对未匹配或匹配到多个候选的店铺进行可视化提示。
- 用户确认后可跳过未匹配店铺继续运行。
- 查询样品订单、抓取订单商品明细、按组长导出 Excel。
- 按“订单号 + SKU”去重后写入钉钉在线表格。
- 在桌面端显示实时日志和运行结果，并可打开输出目录。

迁移后入口为：

```text
马帮流程 / 泰国 Shopee / 网红寄样登记
```

## 3. 强制架构约束

### 3.1 禁止直接复制运行器后继续跨仓库导入

最终桌面端代码不得通过 `sys.path` 引入 `mabang_process`，不得要求用户电脑存在源码仓库，也不得在运行时读取以下开发机路径：

```text
D:\hqyl_project\mabang_process\...
```

需要的业务逻辑必须迁入 `hqyl_desktop/backend`，需要的静态配置必须由 PyInstaller 明确打包。

### 3.2 禁止继续使用原模块全局运行态

原代码通过 `helper.process_config`、`helper.cfg`、`helper.current_groups` 等全局变量切换任务配置。桌面端后台任务可能并行运行，继续使用这些全局变量会发生任务串数据。

请实现每次运行独立的上下文，例如：

```python
@dataclass(frozen=True)
class SampleRegistrationJob:
    username: str
    password: str
    start_date: date
    end_date: date
    output_dir: Path
    target_doc_id: str
    enable_target_update: bool
    groups: tuple[SampleGroup, ...]
```

所有查询、导出和在线写入函数都显式接收 `job`、客户端和 `progress`，不得依赖可变模块全局变量。

### 3.3 账号必须复用桌面端账号管理

- 前端只提交 `account_id`。
- `AppBridge._payload_with_account(..., "mabang")` 负责注入用户名和密码。
- 寄样配置文件不得保存马帮用户名或密码。
- 不要把原 YAML 中的马帮账号密码写进 Python、HTML、JS、测试或日志。
- 泰国马帮地址作为后端内部常量或受控运行配置，不在普通用户界面暴露。

### 3.4 钉钉凭证不得进入前端或用户配置

桌面端安装包当前已把运行时 `config/config.yaml` 打包到根目录。请通过专门的后端配置读取函数获取 `dingtalk.app.rpa` 所需字段：

- 开发环境与冻结环境都要能正确解析路径。
- 凭证不得返回给前端。
- 凭证不得写入日志、异常信息或测试快照。
- 不得再新增一份明文凭证到源码。
- 实机验收时必须验证该钉钉应用对目标文档有读写权限。

## 5. 配置模型与存储

寄样配置单独存储，建议路径：

```text
%APPDATA%\HQYLAutomation\sample_registration.json
```

不要把复杂组长配置硬塞进现有 `AppSettings`。输出根目录仍复用全局 `settings.output_dir`。

配置格式：

```json
{
  "version": 1,
  "target_doc_id": "",
  "enable_target_update": true,
  "groups": [
    {
      "leader": "张三",
      "target_sheet": "张三组",
      "output_file_name": "张三.xlsx",
      "stores": ["店铺 A", "店铺 B"]
    }
  ]
}
```

要求：

- JSON 使用 UTF-8。
- 文件不存在时返回空配置，不报错。
- 配置损坏时返回明确错误，不得悄悄覆盖原文件。
- 保存时先规范化和校验，再原子替换目标文件。
- 组长、店铺去除首尾空白和不可见字符。
- 店铺列表保持输入顺序并去重。
- `target_sheet` 为空时默认使用组长名。
- `output_file_name` 为空时默认使用 `组长名.xlsx`。

校验规则：

- 开启在线写入时必须填写 `target_doc_id`。
- 至少配置一个组长。
- 组长名不得重复。
- 每个组长至少配置一个店铺。
- 输出文件名必须是安全文件名，禁止目录穿越和 Windows 非法字符。
- 输出文件名重复时应报错。
- 日期格式必须有效，开始日期不得晚于结束日期。

## 6. 后端业务设计

### 6.1 数据结构

至少定义：

```text
SampleGroup
SampleRegistrationConfig
SampleRegistrationJob
StoreMatchSummary
SampleRegistrationResult
```

`SampleRegistrationResult` 至少返回：

```text
processed_count
online_append_count
unmatched_store_count
resolved_count
group_count
output_dir
output_files
```

### 6.2 马帮订单能力

从原 `util/mabang_client.py` 迁移本流程实际需要的最小能力：

- 登录并建立订单页上下文。
- 获取订单页店铺列表。
- 按多个店铺 ID、付款时间范围分页查询订单。
- 支持原流程的店铺分片、失败后减小分页、拆分店铺和拆分时间范围重试。
- 批量调用订单商品明细接口。

优先复用桌面端现有 `httpx.Client` 风格，不要把三千多行旧客户端整体复制进来。必须保留以下业务行为：

- 每页行数规范化为马帮支持的值。
- 订单按内部 ID 或平台订单号去重。
- 仅保留带“样品订单”标签的订单。
- 商品明细按“订单编号 + SKU”去重。
- 保留付款时间、订单号、店铺、SKU、中文名、商品总成本、重量等字段。

### 6.3 店铺匹配

迁移 `sample_store_matcher.py` 的匹配规则：

1. 完整店铺名精确匹配。
2. 规范化店铺名匹配。
3. 店铺作用域名称匹配。
4. 只匹配到一个候选才视为成功。
5. 零个候选为“未匹配到马帮店铺”。
6. 多个候选为“匹配到多个马帮店铺”。

匹配结果必须同时：

- 返回给前端展示。
- 在正式运行的输出目录生成“店铺匹配结果.xlsx”。
- 存在异常时生成“未匹配店铺.xlsx”。

### 6.4 Excel 导出

每次运行建立独立目录，建议：

```text
<全局输出目录>\网红寄样登记\YYYYMMDD-HHmmss_<日期标签>\
```

目录内至少包含：

```text
<组长配置的文件名>.xlsx
执行汇总.xlsx
店铺匹配结果.xlsx
未匹配店铺.xlsx（存在异常时）
```

所有 Excel 文件使用 `openpyxl`，文件名必须经过安全处理。即使某组没有数据，也要生成带表头的文件。

### 6.5 钉钉在线表格

迁移本流程所需的最小 API：

- 获取 access token。
- 获取操作人 union ID。
- 获取工作簿 Sheet 列表和 Sheet 元数据。
- 读取目标 Sheet 已有数据。
- 批量追加或更新文本行。

写入规则：

- 每个组长写入其 `target_sheet`。
- 默认填充：寄样日期、订单号、店铺、SKU、中文名、商品总成本、重量。
- 默认用“订单号 + SKU”去重。
- 目标表已有记录不得重复追加。
- 按批次写入，保留原流程的批量限制思想。
- 关闭 `enable_target_update` 时只导出本地文件，不访问钉钉。
- 目标 Sheet 不存在、表头缺列或权限不足时给出明确错误。

不要迁移与用户版无关的店铺映射文档、机器人通知和工作通知逻辑。

### 6.6 日志

所有重要阶段通过 `progress(message)` 输出：

- 登录马帮。
- 获取店铺。
- 店铺匹配统计。
- 每个组长的店铺数、订单数、样品订单数。
- 商品明细抓取进度。
- Excel 导出结果。
- 钉钉去重数量和新增数量。

日志中禁止出现用户名、密码、Cookie、Token、App Secret、完整请求头。

```python

    "ok": True,
    "config": {...}

```

失败时：

```python

```

### 7.3 启动店铺匹配

```python
start_sample_store_match({
    "account_id": "...",
    "config": {...}

```

必须通过 `TaskManager` 异步运行，工具键使用：

```text
sample_registration_match
```

成功结果：

```json

  "unresolved_count": 2,
  "resolved_rows": [],
  "unresolved_rows": []
}
```

### 7.4 启动正式登记

```python
start_sample_registration({
    "account_id": "...",
    "start_date": "2026-06-23",
    "end_date": "2026-06-23",
    "output_dir": "...",
    "allow_unmatched": False,
    "config": {...}
})
```

工具键使用：

```text
sample_registration
```

后端必须再次执行店铺匹配，不能完全信任前端此前的匹配结果。若仍存在未匹配店铺且 `allow_unmatched` 为 `False`，任务应失败并给出清晰说明。

### 7.5 并发限制

- 同一时间只允许一个 `sample_registration` 正式任务运行。
- 前端按钮禁用只是体验措施，后端也必须防止重复启动。
- 匹配任务与正式任务不得共享可变运行态。

### 8.2 页面结构

沿用现有桌面端视觉语言，不引入新框架。页面顶部展示：

- 已配置组长数。
- 已配置店铺数。
- 已匹配店铺数。
- 本次导出行数。

主体使用两个内部页签。

#### 运行登记

- 当前马帮账号，未绑定时复用现有快速绑定流程。
- 日期模式：昨天、指定日期、日期范围。
- 登记表格 ID。
- “同步到在线表格”开关。
- 输出目录及选择按钮。
- 保存配置按钮。
- 匹配校验按钮。
- 开始登记按钮。
- 运行日志与复制日志按钮。
- 完成后显示导出行数、在线追加数、未匹配数和打开输出目录按钮。

#### 组长店铺配置

- 左侧组长列表。
- 添加、删除组长。
- 右侧编辑组长名称、目标 Sheet、输出文件名。
- 店铺列表使用多行文本框，每行一个店铺。
- 显示当前组店铺数量。
- 切换组长时不得静默丢失编辑内容。
- 页面离开或开始任务前自动同步当前编辑内容，并执行完整校验。

### 8.3 未匹配确认

匹配完成后使用自定义模态框展示未匹配表格，不使用浏览器原生 `confirm()`：

- 组长。
- 用户填写店铺。
- 原因。
- 候选马帮店铺。

操作按钮：

- 返回修改配置。
- 跳过未匹配店铺并继续。

默认和推荐操作必须是“返回修改配置”。

### 8.4 任务轮询

现有 `HQYL.startTask()` 不能直接等待匹配任务完成后继续弹窗。应选择一种可复用实现：

- 给 `common.js` 增加等待任务完成/完成回调能力；或
- 在寄样页面实现清晰、可停止的独立轮询。

不得同时启动多个定时器；页面切换或任务结束后必须停止轮询。

## 9. 错误处理

用户界面应输出短错误，完整 traceback 只保留在后台日志。重点处理：

- 未绑定马帮账号。
- 账号登录失败。
- 日期或配置无效。
- 输出目录不可写。
- 马帮店铺/订单接口失败。
- 店铺未匹配或存在多个候选。
- 钉钉凭证缺失、Token 失败、文档无权限。
- 目标 Sheet 不存在。
- 目标表头缺少去重列。
- Excel 文件被占用。

不得把 Python traceback 整段直接显示在主结果卡片或 Toast 中。

## 10. 打包与启动自检

更新 `HQYLAutomation.spec`：

- 新页面和 JS 会随整个 `frontend` 目录自动打包，但测试必须确认文件存在。
- 确保新增 Python 模块可被 PyInstaller 发现。
- 如使用动态导入，加入 `hiddenimports` 或在自检中显式导入。
- 不要把 `mabang_process/thailand` 整个目录作为运行依赖打包。

更新 `launcher/main.py::self_check()`：

- 确认 `frontend/pages/sample-registration.html` 存在。
- 导入寄样服务和所需客户端。
- 读取寄样默认配置但不访问网络。
- 不在自检中登录马帮或调用钉钉。

## 12. 实施顺序

1. 迁移配置模型、清洗和校验，补齐单元测试。
2. 迁移店铺匹配器，补齐单元测试。
3. 扩展桌面端马帮客户端的订单能力。
4. 实现钉钉工作簿最小客户端。
5. 实现无全局状态的寄样服务及假的客户端测试。
6. 添加 Bridge 接口、账号注入和任务并发保护。

## 13. 验收标准

只有同时满足以下条件才算完成：

- 桌面端导航可以进入“网红寄样登记”。
- 用户能维护并持久化组长与店铺配置。
- 用户能复用已绑定马帮账号。
- 匹配校验可展示成功、失败和多候选结果。
- 未匹配时默认阻止运行，确认后可以跳过继续。
- 能按日期抓取样品订单并生成每组 Excel 和执行汇总。
- 能在开启在线写入时按目标 Sheet 去重追加。
- 能在关闭在线写入时完全不访问钉钉。
- 运行日志、结果统计和打开输出目录可用。
