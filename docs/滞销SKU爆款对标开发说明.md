# 滞销 SKU 爆款对标

## 使用方式

入口：BigSeller → 滞销SKU爆款对标。

1. 在平台设置中绑定并选择 BigSeller 账号，配置已有的图形验证码服务。
2. 选择滞销 SKU 源文件和需要处理的工作表。
3. 选择对标指标：浏览量或销量。默认使用浏览量，与旧工具保持一致。
4. 选择输出目录并开始处理。查看查询进度、命中数量、未匹配数量和失败原因，完成后打开结果文件。
5. 失败项会自动等待并补查；仍未完成时点击“继续补查失败项”。程序重启后，选择原文件、原工作表和原指标，再展开“从上次进度继续”，选择输出目录 `BigSeller对标进度` 中的对应进度文件。

新模块使用平台账号与验证码配置。旧 `mabang_process/滞销SKU爆款对标工具.py` 仅用于参考，没有修改；不会复制旧工具内置的账号、密码或固定本机配置。

支持 `.xlsx` 和 `.xls`。在工作表前 10 行寻找“库存SKU编号”“库存SKU”或“SKU”表头，优先识别库存 SKU 列。自动选择有效的“动销总表”，不存在时选择第一个有效业务表。单次最多处理 10000 个不同 SKU。

文本 SKU 保留前导零，纯数字单元格按 Excel 的全零显示格式补齐前导零。SKU 公式需要已有缓存结果；缺少结果或包含 Excel 错误时要求先修正源文件。重复 SKU 按首次出现顺序去重查询。

## 参数

| 参数 | 含义 |
| --- | --- |
| `source_file` | 源 Excel 文件路径 |
| `sheet_name` | 要处理的工作表名称 |
| `metric` | `views` 表示浏览量，`sales` 表示销量，默认 `views` |
| `output_dir` | 结果文件保存目录 |
| `resume_checkpoint` | 可选的 `.sqlite3` 进度文件；仅恢复同一源文件内容、工作表、指标和账号的任务 |

账号和验证码服务配置由平台注入，不作为页面业务参数传入，不保存到结果工作簿。

## 查询口径

查询 BigSeller 当前账号可访问的全部 **Shopee 在售商品**。输入来自所选工作表的“库存SKU编号”列，使用 SKU 模糊搜索；不裁剪子 SKU 后缀，不擅自改为父 SKU 搜索。

请求接口为 POST `/api/v1/product/listing/shopee/pageList.json`。关键参数如下：

```json
{
  "searchType": "sku",
  "searchContent": "输入的 SKU",
  "inquireType": 0,
  "shopeeStatus": "live",
  "status": "active",
  "orderBy": "views 或 sales",
  "desc": true,
  "pageNo": 1,
  "pageSize": 50,
  "timeType": "create_time",
  "startDateStr": "",
  "endDateStr": ""
}
```

`orderBy` 实际传入所选指标值 `views` 或 `sales`。读取 `data.page.rows` 后继续获取后续页，完整查询成功才生成该 SKU 的排名。后续页失败时不能使用不完整的第一页结果声称查询成功。

排名沿用旧业务规则：同一 SKU 在同一家店铺匹配多个商品时，取其中所选指标最高的单个商品；再在各店铺之间选取最高值。该结果不是店铺全部匹配商品指标的总和。相同指标值按店铺名称和店铺 ID 排序，以便结果稳定。

销量使用商品列表的 `sales` 字段。依据是 BigSeller 官方 [Shopee 页面脚本（2026-08）](https://cdn.bigseller.pro/bs-web/2026-08/60675.chunk.98ddce.js)：排序选项 `Comm.All.Sales` 对应 `value:"sales"`，商品行通过 `i.sales` 展示该指标；浏览量选项和行字段对应 `views`。开发时核对了本地保存的该官方脚本。这个证据支持商品列表的“销量”口径，**不支持将它解释为月销量、近 7 天销量或指定日期范围销量**；接口没有加入销售期间筛选。

## 缺数与失败处理

- 请求受进程内全局限速控制，相邻请求起始时间至少间隔 0.75 秒。每页遇到临时网络、服务端或限流错误时最多请求 4 次：网络和服务端错误按 1、2、4 秒退避，限流按 2、4、8 秒退避，并优先遵守更长的 `Retry-After`。
- 本轮未完成的 SKU 进入失败队列，额外最多补查 3 轮，轮次间等待 30、60、120 秒。服务冷却时间更长时按服务要求等待。限流达到请求重试上限或要求等待超过 30 秒时，先结束本轮、保存进度并冷却，不立即换下一个 SKU 继续请求。
- 成功项和已确认未匹配项不再补查；分页失败则从第一页重查该 SKU，不能把前半次查询与后半次查询拼成完整结果。等待期间每 10 秒更新日志。
- 接口返回明确成功、响应结构有效、完整分页没有匹配商品，才计为“未匹配”。
- 登录失效、权限不足、限流重试耗尽、接口错误、响应结构变化及分页不完整，计为查询失败并记录原因。
- 指标为有效数字 `0` 与指标缺失是不同情况。缺失或非法指标不能静默替换为 `0`，再据此生成排名。
- 页面进度按“已确认 = 命中 + 已确认未匹配”计算，分别统计命中、未匹配和失败。失败项不计入已确认，也不计入“没有店铺数据”。自动补查结束后只要仍有未完成 SKU，任务就标记“结果不完整”，保留部分 Excel 和继续补查入口。
- 初始登录失败时任务标记失败，所有未执行项均明确记录原因；即使导出工作簿，也使用“结果不完整”文件名和汇总标记。全部查询完成但导出失败时同样不能标记任务完成，可从进度重新导出且不重复查询。

查询过程中登录失效，全批次最多重新登录一次，并从第一页重新查询当前 SKU。权限不足或重登后仍失败时停止后续请求，处理账号后再继续；未执行的 SKU 计为失败并记录原因。分页总数变化、重复页、重复商品或提前结束均视为结果不完整。单个 SKU 超过 500 页仍未查询完成时失败，要求使用更具体的 SKU。

每个 SKU 的确认结果立即通过 SQLite 事务保存；服务要求的冷却截止时间也在等待之前落盘。进度文件不含账号密码或验证码凭据，恢复时校验源文件 SHA-256、路径、工作表、指标、账号摘要及 SKU 集合，防止混用结果。每次继续任务创建独立新进度文件，保留旧进度。异常退出可能留下同目录的 `-journal` 文件，**请保留整个进度目录**，不要只移动单个数据库文件；恢复会在临时副本上完成日志恢复，不修改原进度。

这里的“完整”是每个输入 SKU 均得到当前账号可见的 Shopee 在售范围内的明确结果；不意味着每个 SKU 都一定有店铺，也不表示超出账号权限或其他商品状态范围的数据已经覆盖。

## 文件与结果

输出写入带时间戳和唯一后缀的新 `.xlsx` 文件，不覆盖源文件。对于 `.xlsx`，保留原工作表、原业务内容和格式，仅回填所选指标的结果并增加对标明细。选择销量时使用销量结果列，保留原有浏览量结果，便于两种指标对照。

`.xls` 会转换为 `.xlsx`，只保留单元格值与基本格式，公式采用原文件缓存值；页面和任务日志明确提示这一限制。需要完整保留公式和格式时，先使用 Excel 另存为 `.xlsx`。

原表的“库存SKU编号”用于定位输入。“浏览量第一店铺”及旧别名“浏览量第一”“浏览量TOP1”作为已有浏览量结果列识别；销量具有对应的独立结果列。

原表回填以下四列，其中“浏览量”在销量模式下替换为“销量”：

| 列 | 内容 |
| --- | --- |
| 浏览量第一店铺 | 指标最高的店铺，兼容已有结果列别名 |
| 浏览量指标值 | 获胜单个商品的指标数值 |
| 浏览量对标状态 | 已匹配、未找到商品、查询失败 |
| 浏览量对标说明 | 未匹配、失败或未执行原因 |

没有对应结果表头时，在工作表末尾增加列，不占用“空表头但已有数据”的业务列。未找到或失败时清空所选指标的旧店铺及数值，并写明本次状态，避免将历史结果误认作本次成功。

独立明细表名为“BigSeller浏览量对标明细”或“BigSeller销量对标明细”，列为 `SKU`、`店铺`、`指标值`、`店铺数`、`Item ID`、`状态`、`说明`。每个不同 SKU 对应一行，重复 SKU 的结果同时回填所有源表行。SKU、店铺名及 Item ID 按文本写入，输入以 `=` 开头时不会变为公式。汇总数量按不同 SKU 统计，同时提供源表总行数。

页面最多预览 500 个 SKU，Excel 包含全部结果。再次处理已带明细的文件时，复用同名且表头一致的明细表；同名表内容不兼容时使用新名称，保护原有工作表。

另外生成“BigSeller浏览量对标汇总”或销量汇总，记录完成状态、源行数、不同 SKU 数、已确认数及补查统计。未完成文件名带 `_结果不完整`，并增加“BigSeller浏览量待补查”或销量待补查表，列出 SKU、失败原因、查询轮数和源表行号。导出前再次核对结果与输入 SKU 一一对应，完整状态必须同时满足零失败和计数一致。生成的汇总、待补查表带内部标记，用户同名表保留并为新表另起名称。

## 用户样本诊断

只读分析的文件为 `9月滞销sku__Sheet1_BigSeller浏览量对标_20260904_144509.xlsx`。结果来自 `Sheet1`，第二行为表头，第三行至第 3726 行为数据；A 列为“库存SKU编号”，J 列为“浏览量第一店铺”。

| 范围 | SKU 行数 | 已填店铺 | 空白 |
| --- | ---: | ---: | ---: |
| 全部 | 3724 | 2127 | 1597 |
| 马来西亚 MY01 仓 | 2339 | 1351 | 988 |
| 马来西亚 MY02 仓 | 1385 | 776 | 609 |

空白占全部行的 42.88%，涉及 1595 个不同 SKU。空白在两个仓库均出现；工作簿只有店铺名，没有查询状态和错误原因，因此不能仅凭工作簿判断每条空白是无匹配、无权限还是请求失败。

存在多次连续成段空白：`J23:J53` 共 31 行，`J74:J105` 共 32 行，`J134:J163` 共 30 行，`J191:J222` 共 32 行。旧版使用 10 个线程，没有全局请求间隔，失败采用统一短暂等待再重试。这些证据使“并发触发限流或批次请求失败”成为优先排查方向，**尚未确认它是该文件的真实根因**。

旧代码中可以直接确认的问题包括：

1. 只读取第一页 50 条商品，遗漏后续候选店铺。这个缺陷通常无法单独解释第一页也完全空白的情况。
2. 缺少 `data/page/rows` 时降格为空结果，没有区分响应结构异常。
3. 查询失败保留原值，原值为空时输出仍为空；没有在工作簿中记录失败原因。
4. “未找到”数量按总行数减命中数计算，包含查询错误。
5. 缺失、非法或含千分逗号的指标被转成 `0`，仍然选出一家店铺。
6. Excel COM 导出失败后使用 pandas 重建工作簿，会损失原格式等内容。

建议真实补查样本为 `A7=hqs56146aa`、`A11=742404020740`、`A23=hqs41077a`、`A24=hqs41077b`、`A27=hqs41077d`。其中相邻 `A22=hqs41077e` 已填店铺，可作为同款变体对照。这些样本用于验收，不能在尚未查询成功时宣称已恢复数据。
