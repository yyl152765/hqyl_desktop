# TEMU 活动报名导出 开发说明

> 对应需求：TEMU 半托管活动批量报名（`superbrowser_process/docs/temu_activity_registration_development.md`）
> 本说明只覆盖**第一阶段：数据导出**。匹配改价、审核包、分批提交与结果核查尚未实现。

## 1. 使用方式

1. 侧栏「紫鸟流程 → 活动报名导出」，或开发入口 `--page=temu-activity-export`。
2. 选择紫鸟账号（顶栏账号栏，未绑定会直接弹出绑定对话框）。
3. 在「紫鸟店铺名」里每行填一个店铺名，可填完整名，也可填能唯一匹配的片段（如 `店A`）。
4. 勾选本次站点（菲律宾 / 马来西亚 / 泰国，至少一个）。
5. 确认运行日期（北京时间，默认当天，不允许选择未来日期）与输出目录。
6. 首次在真实环境使用前，先点「检查页面结构」，按返回的标签、活动类型和商品计数核对页面元素是否与本实现一致。
7. 点「开始导出」。逐店进度写入右侧运行日志，结果表格实时更新；失败的店铺可用「重试失败店铺」，已成功的店铺不会重跑。

## 2. 逐店执行的动作

| 步骤 | 动作 | 失败时的处理 |
| --- | --- | --- |
| 1 | 校验紫鸟店铺 ID、名称与 TEMU 平台标识 | 该店失败，继续下一家 |
| 2 | 打开卖家后台，按「店铺营销 → 营销活动 → 批量报名活动」进入活动页 | 未进入活动页即失败，不影响其他店铺 |
| 3 | 选中限时秒杀、官方大促、专题活动 | 缺少任一活动类型即失败（活动范围无法保证） |
| 4 | 专题主题先「全选」，再取消名称含「清仓/清货/甩卖/清库存」的主题 | 仍有清仓主题被选中即失败 |
| 5 | 勾选本次站点 | 页面找不到站点选项或站点不全则失败 |
| 6 | 「选择商品」→ 每页 100 条 → 逐页全选 → 校验已选数与平台总数一致 | 计数不一致即失败，不导出 |
| 7 | 生成并下载模板（浏览器内 blob 捕获，不使用历史下载文件） | 超时或文件不完整即失败 |
| 8 | 打开下载文件核对工作表、表头、站点覆盖、报价/库存行数 | 结构不符或站点越界即失败 |

页面级核对（活动类型、清仓排除、商品计数）记录在 `evidence` 里；拿不到页面信号时记录为未核实，但第 8 步的文件核对是**强制**的。

## 3. 参数

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `store_names` | 是 | 多行文本，每行一个店铺名，最多 200 个；大小写不敏感去重 |
| `sites` | 是 | `PH` / `MY` / `TH` 子集，至少一个，不允许重复 |
| `business_date` | 否 | `YYYY-MM-DD`，默认北京时间当天；不允许晚于当天 |
| `output_dir` | 否 | 留空使用本功能独立输出目录，默认 `桌面/log/TEMU活动报名导出` |

## 4. 口径

- **一次导出 = 一个店铺 × 本次勾选站点**。站点是页面筛选条件，导出后按模板 I 列反查，出现未勾选站点或缺少勾选站点都判失败。
- **四类计数分别记录，不能互相替代**：SPU 数、SKU ID 数、报价行数、库存行数。日志和结果表里都分开显示。
- **报价行按非空业务键统计**（活动主题 / SPU ID / SKU ID 至少一个非空），表头不计入。
- **标识按文本读取**：SKU ID、SPU ID 不做数值转换，避免长整数丢精度。
- **清仓识别**用主题名关键词匹配，当前关键词集为 `清仓 / 清货 / 甩卖 / 清库存`；命名变体需要按真实页面继续补充。
- **原始文件不改动**：`raw/` 下保留浏览器下载的原件，`results/` 下是同内容的命名副本，便于交付。

## 5. 输出结构

```
TEMU活动报名导出_<时间戳>_<run_id>/
├── manifest.json            批次清单：状态、站点、逐店计数、证据、错误
├── raw/001_<店铺>/attempt_1/活动报名模板.xlsx
├── results/<店铺>_<店铺ID>_<站点>_<运行日期>_活动报名模板.xlsx
└── logs/run.log
```

`manifest.json` 关键字段：

- 批次级：`schema`、`run_id`、`profile`、`status`、`business_date`、`sites`、`error`
- 店铺级：`store_id`、`store_name`、`status`、`attempts`、`raw_file`、`result_file`、`sha256`、`quote_rows`、`stock_rows`、`spu_count`、`sku_count`、`topic_count`、`exported_sites`、`evidence`、`error`
- `evidence` 内含 `activity_types`、`clearance`（排除前后的主题数与被排除的主题名）、`products`（分页数、是否切到 100 条、总数/已选数、是否一致）、`seller_sites`

前端「导出结果」汇总栏显示：成功店铺数、报价行合计、库存行合计、站点分布。

## 6. 限制与注意事项

- **页面元素尚未实机校准**。标签集集中在 `backend/services/temu_activity_page.py` 顶部（`MENU_SALES`、`MENU_ACTIVITY`、`MENU_BATCH`、`ACTIVITY_TYPES`、`PRODUCT_ENTRY`、`SELECT_ALL`、`PAGE_SIZE`、`NEXT_PAGE`、`GENERATE`），实机核对后改这里即可，不要在各步骤里散写字符串。
- **站点显示值**（`菲律宾站` 等）在 `temu_activity_workbook.SITE_DISPLAY` 里维护，三个站点都要用真实店铺验证一次。
- **不提交、不改价、不报名**，因此重复运行是安全的；但同一批次内已成功的店铺不会重跑，避免覆盖已核对的文件。
- **与其它 TEMU 导出互斥**：共用 `_temu_export_lock`，同一时间只允许一个 TEMU 浏览器导出任务。
- **不写凭据**：`manifest.json` 只记录 `profile`（账号哈希），不含公司/账号/密码。
- **凭证与失败口径**：任一步失败即该店失败并记录原因，其余店铺继续；紫鸟认证失效或店铺未确认关闭会停止后续店铺。
- 后续阶段（ERP 匹配改价、审核包与批准绑定、≤3000 行拆批、提交与结果核查）不在本功能范围内，不要在本页面加提交按钮。

## 7. 2026-11-04 测试记录

- 回归结果：153 项测试、46 个子场景通过，包含活动导出、前后端桥接、紫鸟浏览器、TEMU 登录、客户端启动与桌面入口。
- 增加离线 Edge DOM 测试：运行实际页面识别脚本并勾选站点，覆盖三站点的 7 种显示名称；连续执行不会把已勾选站点取消。
- 修复页面识别脚本缺少站点标签的问题；原模拟浏览器自行补全了站点，未能发现真实识别脚本的遗漏。
- 修复下载文件仍含清仓报价时被误判成功的问题；页面已排除清仓也必须复核文件，发现清仓报价即失败。
- 结果文件名增加稳定店铺 ID，防止不同店铺名称在非法字符替换或截断后重名而互相覆盖。
- 实机结果：CLI 账号认证和店铺目录读取正常；代表菲律宾店铺的桌面完整导出在 TEMU 登录确认阶段报「无法唯一确认 TEMU 登录控件」。本轮未取得真实活动模板，活动页筛选、全量商品选择和下载仍未完成实机验证。

Windows 终端运行探测脚本时，如默认编码为 cp950，可先设置 `$env:PYTHONIOENCODING='utf-8'`，避免中文日志导致 `UnicodeEncodeError`。CLI 的登录状态与桌面 WebDriver 自动化模式是两个独立的运行检查，不能用前者通过代替后者验证。
