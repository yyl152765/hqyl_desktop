# 开发与销售收入汇总导出——开发文档

## 1. 模块定位

- 模块名称：开发与销售收入汇总导出
- 业务归属：采购流程
- 数据来源：马帮 ERP 商品销量报表
- 统计时间口径：付款日期
- 币种口径：美元（`moneyType=US`）
- 唯一金额指标：收入-订单金额

## 2. 用户操作

1. 选择付款开始日期和付款结束日期。
2. 在开发员姓名输入框中按“一行一个姓名”录入待统计人员；也可勾选“遍历全部开发员和销售员”进入全部人员模式。
3. 点击“开始汇总并导出”。
4. 系统跳过在马帮开发员选项中不存在的姓名，并在运行日志中显示跳过名单。
5. 系统生成一个 Excel 文件，内含“开发员”和“销售员”两个子表。

## 3. 姓名匹配与同名规则

马帮人员选项使用独立人员 ID。姓名匹配时允许输入纯姓名，系统会在匹配时忽略工号前缀和岗位后缀，但在查询和导出时必须保留原始人员 ID 与原始显示名称。

例如，输入 `黄茵茵` 时，如果马帮同时存在：

- `黄茵茵-开发>1`
- `A1018-黄茵茵-开发`

则两个选项都要命中。系统按两个独立 ID 分别查询，并在“开发员”子表中保留为两行，不合并金额。`>1` 不是数量字段，不得删除或折叠人员记录。

## 4. 数据处理流程

1. 使用当前绑定的马帮账号登录。
2. 读取商品销量报表页面的 `developid[]` 和 `saleid[]` 人员选项。
3. 将用户输入的姓名与 `developid[]` 选项匹配，一个姓名可命中多个独立 ID。
4. 按命中的开发员 ID 逐个调用商品销量报表导出，固定条件为：
   - `timeKey=payTime`
   - 用户选择的付款日期区间
   - `moneyType=US`
   - 当前开发员的 `developid[]`
5. 每份结果只读取“销售员”和“收入-订单金额”，跳过“合计/总计”行，防止重复计算。
6. 开发员金额按当前开发员 ID 汇总。
7. 指定姓名模式下，销售员金额按同一批开发员结果中的“销售员”字段汇总，因此两个子表合计金额应一致。
8. 空白或 `--` 销售员统一记为“未分配销售员”，保证收入不丢失。

### 4.1 全部人员模式

全部人员模式会读取马帮页面中的全部 `developid[]` 与 `saleid[]` 选项，再按每个独立人员 ID 并发查询销量报表 `tableFoot` 中的“收入-订单金额”合计。没有收入的人员返回 0 并保留在对应子表中；带 `>1` 的名称按原始名称单独查询、单独保留，不与其他同名人员合并。该方式避免下载每个人的商品明细，但统计口径仍是商品销量报表、付款日期和美元。由于开发员、销售员是分别按各自筛选字段独立遍历，两个子表的合计不要求相等。

## 5. Excel 输出规范

文件名：

` 开发与销售收入汇总_YYYYMMDD_YYYYMMDD_YYYYMMDD_HHMMSS.xlsx `

### 5.1 开发员子表

| 开发员 | 收入-订单金额（USD） |
| --- | ---: |
| 马帮原始开发员名称 | 美元金额 |
| 合计 | 全部命中开发员的美元金额 |

### 5.2 销售员子表

| 销售员 | 收入-订单金额（USD） |
| --- | ---: |
| 销售员名称 | 美元金额 |
| 合计 | 全部销售员的美元金额 |

金额使用数值单元格和美元格式，保留 4 位小数，便于后续求和及对账。

## 6. 异常与校验

- 未绑定马帮账号：引导用户先绑定账号。
- 日期格式无效或开始日期晚于结束日期：禁止启动任务。
- 姓名输入为空：禁止启动任务。
- 部分姓名不存在：跳过不存在的姓名，继续处理其他命中人员。
- 全部姓名都不存在：终止任务并提示未匹配到开发员。
- 马帮返回空数据：该开发员仍在子表中保留，金额为 0。
- 马帮返回非 CSV 或缺失必需字段：终止任务，不生成不完整报表。
- “开发员”和“销售员”子表合计不一致：视为数据异常，禁止保存。

## 7. 验收标准

1. 界面位于马帮流程的“采购流程”分类。
2. 界面有付款开始/结束日期和一行一个姓名的输入框。
3. 输入 `黄茵茵` 时，` 黄茵茵-开发>1 ` 和 ` A1018-黄茵茵-开发 ` 作为两个开发员分别查询、分别导出。
4. 导出文件只有“开发员”和“销售员”两个子表。
5. 两个子表只展示人员名称和“收入-订单金额（USD）”。
6. 金额取自马帮商品销量报表的美元口径，按付款日期筛选。
7. 指定姓名模式下，开发员与销售员子表的合计金额一致；全部人员模式分别保留两个维度各自的合计。
