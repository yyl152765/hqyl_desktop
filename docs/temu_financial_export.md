# TEMU 财务报表导出

在桌面平台的“紫鸟流程 → 财务报表导出”中，选择有店铺权限的紫鸟账号，填写店铺名称（每行一个）、开始日期、结束日期和输出目录，点击“开始导出”。支持完整紫鸟店铺名或能唯一匹配的简称；汇总文件始终写入匹配后的完整紫鸟名称，无需填写运营名。

程序依次处理各店铺：账户资金 → 对账中心 → 日期选择（自定义）→ 查询 → 导出 → **导出列表 + 账务详情** → 确认 → 导出历史 → **下载财务明细（全球）**。账务类型为全部，资金流向为全部，无金额限制。日期包含起止两天，并核对新任务的查询时间为开始日 00:00:00 至结束日 23:59:59。只选择本次新生成的任务，不复用旧任务或下载其他区域的报表。

输出目录独立保存，默认位于 `桌面/log/TEMU财务报表导出`。每次运行创建新的批次目录：

- `raw/`：平台原始下载文件。
- `results/`：逐店工作簿与一个合并总表。
- `manifest.json`：日期、店铺、任务确认信息、逐店状态、文件路径和各 sheet 行数。
- `logs/run.log`：逐店运行日志。

每个有表头的 sheet 最前面增加“店铺名”列，逐条填写完整紫鸟名称。不同店铺的同名 sheet 按字段名及表头层级对齐并向下追加，只保留一组表头。支持普通单行表头和“结算”sheet 的两行合并表头，保留商品信息分组，并将“店铺名”表头纵向合并；数据行数不包含表头。额外字段、新增 sheet、只有表头的 sheet 和空 sheet 均保留。数字及数字格式、文本订单号和原始字段值保留；以“=”开头的文本保持文本类型。原表已有“店铺名”时，将该原字段改名为不冲突的“店铺名（原表）”或带序号的名称，保留原字段内容。

对账中心位于中国卖家中心域名，全球下载可能新开全球中心授权页。程序核对新页面的全球下载目标和店铺名称后，只确认当前下载的授权，不操作其他已打开的授权页。账号登录或人工验证仍需用户完成。

自 0.2.90 起，身份校验等待真实店名加载，空容器及占位符不会被当作已加载的身份。同一店名重复渲染只算一个身份，出现不同店名或与所选紫鸟店铺不匹配时仍停止导出。页面跳转造成的读取中断只在身份等待期间按原截止时间重读；登录失效、人工验证及浏览器连接错误不会当作有效身份放行。

成功店铺的结果可通过“打开合并总表”查看。部分店铺失败时，只合并成功店铺，并在页面和文件名中明确标注“不完整”；全部失败时不生成总表。重跑会创建新批次，不覆盖旧结果。原始文件保持不变，逐店文件和总表通过校验后才发布到结果路径。

当前接收 `.xlsx`，单个下载文件上限 128 MiB；超出 Excel 单 sheet 行列上限、表头为空或重复、公式、错误值、损坏文件、登录失效、人工验证及无法唯一关联新任务时，会报告具体错误，不将失败当作零数据。

开发入口：`.\.venv\Scripts\python.exe desktop_entry.py --page=temu-financial-export`。

自动测试包含多店铺多 sheet 文件样例、合并表头、失败批次、账号与输出目录隔离、下载校验、授权店铺校验、前端交互，以及重现截图结构的本地浏览器模拟页面。2026-11-04 已使用紫鸟 CLI 完成两家授权店铺的 2026-10-01 至 2026-10-31 全球明细下载，并使用本模块完成汇总及逐单元格核对；用户完成了登录，其中一次全球中心授权通过电脑操作完成。桌面程序整批无人值守流程及新的原生授权分支仍需单独实机验收。真实账号、店铺清单、Cookie、密钥和业务报表仅保留在忽略目录，不得提交到公开仓库。

自 0.2.91 起，进入对账中心还须等待查询表单就绪。店名已出现但表单仍在异步加载时不点击侧栏；等待期间持续核对身份，表单超时会明确提示。

自 0.2.92 起，原生桌面浏览器从中国卖家中心对账地址启动财务流程，不再把全球卖家中心登录成功作为前置条件；中国页面仍须通过登录状态和店铺身份校验，全球确认仅在本次全球下载时处理。
