# BigSeller 对标进度保存失败排查说明

日期：2026-09-05。

## 已确认的现象

截图显示浏览量对标已确认 495 / 3721 个 SKU，随后在 `Checkpoint.save_result()` 调用 SQLite 保存时停止。登录与前面的商品查询已经成功；这次故障发生在本地进度写入阶段。

0.2.50 将 SQLite 文件占用、磁盘满、只读、磁盘 I/O 以及结果文字编码等异常统一显示为“检查输出目录的权限和磁盘空间”。因此，仅凭这张截图不能确定故障电脑的具体原因。

截图的源文件与输出目录位于 `C:\Users\Administrator\Desktop`，当前排查工作区位于另一用户目录，尚未获得故障电脑的磁盘余量及原进度文件，不能用开发机磁盘情况代替现场证据。

## 验证结果

- 本地源 SKU 顺序与截图最后两项一致。对紧接第 495 项之后的第 496 个 SKU，使用正式查询函数执行浏览量只读查询，返回 18 家店铺；结果文字没有未配对代理字符，临时 SQLite 保存及读回均成功。这不能复现故障电脑的文件系统状态。
- 纯合成测试分别触发真实 SQLite 锁和数据库页数上限，以及非法 Unicode 编码，确认这三种错误在 0.2.50 中都会变成同一个提示。
- 三类故障均保持事务回滚：之前提交的结果保留，本次失败的批次不部分提交。
- 本轮针对性回归共 80 项测试、94 个子测试通过：进度存储 19 / 41，查询及恢复 34 / 25，工作簿、页面和任务管理 27 / 28；检查了中途保存失败停止查询、旧结果保留、只补查未完成项及导出失败时仍提供进度路径。

## 已补充的源码处理

- 按安全的 SQLite 基础错误码区分占用、空间不足、只读、磁盘 I/O、文件损坏和打开失败；编码、序列化与操作系统错误单独说明，不回显原异常中的业务数据。
- 只对短暂的 `SQLITE_BUSY` / `SQLITE_LOCKED` 最多尝试 3 次，额外等待 0.25、0.5 秒；其他错误立即停止写入和后续商品请求。
- 保存成功后才把当前 SKU 计入已确认结果。保存失败时保留已提交记录的统计、进度路径和恢复入口，并尝试导出已确认的部分结果；任务保持未完成。
- 服务冷却时间无法持久化时继续保持立即停止，避免把冷却保存失败当作普通查询失败重试。

这些是源码改进，不表示已确认或修复故障电脑的磁盘问题；现有 0.2.50 安装包不会因源码变化自动更新。

## 现场恢复

1. 保留 `C:\Users\Administrator\Desktop\BigSeller对标进度` 整个目录，包括可能存在的 `-journal` 文件。日志里的 495 条已确认进度是在每次提交成功后才显示的。
2. 核实故障电脑的客户端版本、C 盘剩余空间，以及进度目录是否被移动、清理或其他程序打开。
3. 处理空间或占用问题后，保持原源文件、Sheet1、浏览量和相同账号，从“从上次进度继续”选择该次进度文件。恢复会校验旧文件并创建新的独立进度，只查询未完成项。
4. 如桌面目录存在写入限制，可将输出目录改为另一处确认可写、有足够空间的目录。输出目录允许改变，原源文件内容和恢复身份条件必须保持一致。

仍需故障电脑的空间、版本和进度文件证据，才能区分具体现场原因；不要仅根据旧版通用提示断言磁盘已满。
