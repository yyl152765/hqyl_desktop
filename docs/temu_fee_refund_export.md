# TEMU 面单费与退货退款导出

## 运行方式

1. 在桌面平台的“管理账号”中绑定并选择有目标店铺权限的紫鸟账号。
2. 打开“面单费与退货退款导出”，输入店铺名，每行一家。优先使用完整紫鸟店铺名；输入简称时必须只匹配一家店铺。未匹配、同名歧义或多个输入指向同一家店铺时，需修正名称后再运行。
3. 选择开始日期、结束日期和输出目录，点击“开始导出”。一次运行按店铺顺序处理下列三类报表，再合并为一个 Excel 文件。完成后点击“打开合并总表”查看结果。

运营名无需手工输入。程序使用匹配到的**完整紫鸟店铺名**，将第一个连字符前的首段作为运营名。例如虚构名称 `运营甲-站点-店号-公司-卖家名` 的运营名为 `运营甲`。名称不含可识别的首段时会停止，不能用登录账号代替运营名。

## 日期和固定条件

日期范围包含开始和结束日期。三类导出均在 TEMU“全球”区域处理。

| 报表 | 后台路径与固定条件 | 日期字段 |
| --- | --- | --- |
| 发货面单费 | 账户资金 → 发货面单费 → 已出账 | 账单支出/退款时间 |
| 退货面单费 | 账户资金 → 退货面单费 → 退至商家仓 | 账单支出/退款时间 |
| 退货退款 | 订单管理 → 退货/退款 → 售后单导出；类型为退货退款，状态为已退款，国家/地区为全部 | 售后单创建日期 |

程序会重置额外筛选、确认日期回显和查询完成，再关联本次生成的导出任务。面单报表的下载行数需与页面账单数一致；文件中的日期和币种也会核对。导出历史出现多个无法区分的新任务时会报告失败，避免下载其他任务的文件。

## 结果目录与状态

本功能独立保存输出目录设置，默认位于 `桌面/log/TEMU面单费与退货退款`，也可在页面修改。每次运行新建带时间和随机标识的批次子目录，包含：

- `raw/`：各店铺、各类报表的原始下载文件。
- `results/`：一个合并总表，以及保留的逐店明细。合并总表包含“发货面单费”“退货面单费”“退货退款”三个工作表，同类数据按店铺顺序向下追加，只保留一行表头。每条记录带运营和完整紫鸟店铺名，其后保留原报表字段。
- `manifest.json`：批次条件、逐店逐项状态、文件路径、行数及验证信息，用于核对本次结果。

“退货退款”工作表按参考格式增加首列“月份”。同一个月的导出区间填写月份，例如“9月”；跨月区间填写所选起止日期。无数据的类别保留工作表和表头，不补造明细行。

页面优先提供“打开合并总表”，也可分别打开逐店明细或整个结果目录。明确查询为零条时显示“无数据”，不将失败或尚未加载的页面当作零数据。部分报表失败时，成功数据仍可合并，但页面会明确标注“合并总表不完整”，并保留逐店错误；修正原因后重新运行会创建新批次。

售后单导出达到平台 **10,000 条**上限时会判为无法确认完整，请缩小日期范围后重新运行。单个下载文件的接收上限为 **128 MiB**。登录失效、人工验证、筛选控件变化、下载异常或文件校验失败会显示具体错误。

## 开发联调

桌面功能使用页面选择的项目绑定账号。CLI 仅作为开发联调工具；若本机配置了多个 CLI 账号，可用以下命令检查和切换，所选配置应与紫鸟客户端登录账号一致：

```powershell
ziniao-cli config list
ziniao-cli config use '<配置名称>'
ziniao-cli doctor
```

不要将个人账号、店铺名单、Cookie、密钥或内部人员映射写入公开文档或提交到公开仓库。实际店铺、日期、三类文件和验证结论应记录在独立验收记录中；本文不替代实店验收，也不表示所有店铺和平台页面版本均已验证。
