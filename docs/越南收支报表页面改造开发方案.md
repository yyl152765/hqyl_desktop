>
> 项目目录：`D:\hqyl_project\hqyl_desktop`
>
> 本次目标：将现有“越南收支核对”页面改造成以财务结果为中心、流程清晰、异常可追踪的“越南收支报表”工作台。

## 0. 给开发人员的执行要求

开始编码前，请完整阅读本文档，不要只做标题替换或局部样式调整。

实施时必须遵守以下约束：

1. 项目技术栈为 Python 3.12、pywebview、静态 HTML、CSS 和原生 JavaScript，不要引入 React、Vue、Node 构建链或外部 CDN。
2. 复用现有 `window.pywebview.api`、`HQYL.boot()`、账号管理、任务轮询和日志能力。
3. 不改动紫鸟、马帮的采集业务口径，不改变最终利润计算公式；本次重点是页面信息架构、结果展示、异常表达和状态恢复。
4. 不直接修改 `dist/`、`build/`、`release/` 中的构建产物；只修改源码，最终由构建脚本重新生成。
5. 当前 Git 工作区存在其他用户改动及未跟踪文件，只修改本文档明确列出的目标文件，不清理、不覆盖、不回退无关改动。
6. 保留现有内部路由、页面 key、任务 key、API 名和历史目录，以兼容已有批次。
7. 每完成一个实施阶段，都要运行对应自动化测试，并使用内置预览模式完成截图检查。
8. 所有新增用户文案必须使用业务语言；技术错误码、堆栈、manifest 路径只能放在“技术详情”中。

## 1. 改造背景

当前页面代码位于：

- 页面结构：`frontend/pages/vietnam-income-reconciliation.html`
- 页面逻辑：`frontend/assets/pages/vietnam-income-reconciliation.js`
- 页面样式：`frontend/assets/app.css`
- 侧栏与公共任务逻辑：`frontend/assets/common.js`
- Python Bridge：`backend/app_bridge.py`
- 最终报表处理：`backend/services/vietnam_final_reconciliation.py`

当前页面已经覆盖完整业务流程：

1. 选择核对月份、紫鸟账号、输出目录和店铺。
2. 创建批次及 `manifest.json`。
3. 采集紫鸟补贴订单。
4. 采集紫鸟广告消费、联盟消费、广告补贴。
5. 拉取马帮收支明细及汇总，并校验订单数和应收货款。
6. 拉取三段退款并合并去重。
7. 填写上月利润率。
8. 生成最终工作簿、摘要、未匹配清单和处理日志。

业务能力已经基本完整，但页面仍呈现为“开发阶段的采集控制台”，而不是“用户查看和处理月度财务报表的工作台”。

### 1.1 当前主要问题

#### 问题一：页面过长，所有内容同时展开

建批次、账号、日志、店铺状态、马帮校验、退款、最终处理全部纵向铺开。用户进入页面后无法快速判断：

- 当前完成到哪一步；
- 现在应该点击哪个按钮；
- 哪一项阻断了后续操作；
- 报表是否已经生成；
- 生成后应该在哪里查看结果。

#### 问题二：页面以过程为中心，没有真正展示报表结果

当前首屏展示的是月份、店铺数、就绪数据项和 manifest，而不是收入、支出、退款、利润等财务结果。

后端实际上已经计算了以下店铺级数据：

- 调整后应收货款；
- 所有支出项；
- 调整后运费；
- 调整后包材费；
- 实际退款；
- 实际联盟费用；
- 最终广告花费；
- 利润；
- 利润率。

这些数据目前只写入 Excel，前端没有展示。

#### 问题三：步骤状态表达不准确

现有 `renderPhaseStrip()` 中：

- 紫鸟阶段始终为 `active`；
- `active` 同时承担“已到达”和“当前步骤”两种含义；
- 最终结果阶段始终不会激活；
- 没有 `completed`、`locked`、`error` 等明确状态。

#### 问题四：用户界面残留技术和开发文案

当前存在以下不应面向业务用户的文案：

- “开发阶段”；
- “里程碑 A”；
- “打开 manifest”；
- “待接入”；
- “待开发”；
- “查看第三阶段说明”。

同时，“当前范围”仍提示暂不接入最终财务计算，但同页已经支持生成最终工作簿，属于过期说明。

#### 问题五：异常、恢复和结果入口不足

- 马帮校验失败只显示少量差异文本，店铺级差异不突出。
- 采集失败原因、重试次数和受影响店铺没有系统展示。
- 最终未匹配记录只有数量，没有前端清单。
- 最终成功主要通过日志和 Toast 告知，没有固定结果卡片。
- 页面只有一个 `taskKey`，只能恢复补贴采集任务；马帮、退款和最终生成任务不能完整恢复。
- 利润率使用自由文本输入，容易漏填、重复或格式错误，并且刷新后丢失。

## 2. 改造目标

### 2.1 产品目标

将页面从“采集任务控制台”改造成“越南 Shopee 月度收支报表工作台”。用户进入页面后，应能在 5 秒内回答以下问题：

1. 我现在查看的是哪个月份、哪个批次？
2. 报表是否已经生成？
3. 当前收入、支出、退款、利润是多少？
4. 是否存在异常或未匹配记录？
5. 如果还没生成，下一步应该做什么？

### 2.2 体验目标

1. 报表生成后，默认先看结果，不再先看采集表单。
2. 报表尚未生成时，默认定位当前步骤，只展开当前需要处理的内容。
3. 页面任一状态只保留一个明确的主操作。
4. 禁用操作必须显示具体原因，不能只变灰。
5. 异常信息必须包含“发生了什么、影响什么、下一步怎么做”。
6. 日志和技术字段默认收起，不占据首屏。
7. 页面刷新、切换批次或任务完成后，状态和数据能够正确恢复。

### 2.3 成功指标

本次改造完成后，应满足：

- 首屏不再出现大块空日志区域；
- 最终报表生成后，首屏可见财务 KPI 和店铺汇总；
- 用户无需阅读日志即可完成主流程；
- 所有失败和阻断状态均有可理解的原因与下一步操作；
- 页面不再出现旧模块名及开发残留文案；
- 旧批次、旧 manifest 和旧目录仍能打开；
- 原有采集与生成结果不发生业务回归。

页面及用户可见产品名称统一为：

```text
汇总紫鸟与马帮数据，核对越南 Shopee 月度收支并生成利润报表。
```

建议侧栏副标题：


以下位置必须同步修改：

| --- | --- | --- |
| HTML `<title>` | 越南收支核对 | 越南收支报表 |
| 页面 H1 | 越南收支核对 | 越南收支报表 |
| 面包屑末级 | 收支核对 | 收支报表 |
| 侧栏主标题 | 越南收支核对 | 越南收支报表 |
| 侧栏副标题 | 紫鸟+马帮数据核对 | Shopee 月度收支与利润 |

业务动作中的“核对”“校验”“差异核对”等词可以继续保留，因为它们描述的是功能，不是模块名称。

### 3.2 必须保持不变的内部标识

以下内部标识不要因改名而修改：

- 页面文件名：`vietnam-income-reconciliation.html`
- 页面脚本名：`vietnam-income-reconciliation.js`
- 启动参数：`--page=vietnam-income-reconciliation`
- 页面 key：`vietnam_income_reconciliation`
- 各类 `vietnam_*` Python API 名；
- 任务 tool key；
- manifest schema；
- 历史输出目录：`越南收支核对/{YYYY-MM}/{run_id}`。

原因：这些标识已被路由、任务恢复、测试及历史批次引用，直接改名会引入不必要的迁移风险。

### 3.3 新旧文件兼容规则

1. 新生成的 Excel 使用新名称 `越南Shopee收支报表_{period}_{stamp}.xlsx`。
2. 已存在的旧 Excel 不重命名、不迁移。
3. 页面打开结果文件时必须读取 manifest 中的 `final.output_file`，不能通过固定文件名猜测。
4. 历史批次仍从旧目录 `越南收支核对` 中读取。
5. 任何历史功能都必须同时支持旧文件名和新文件名。

## 4. 目标信息架构

页面采用“全局报表头部 + 三个业务 Tab + 技术详情抽屉”的结构。

```text
┌──────────────────────────────────────────────────────────────┐
│ 越南收支报表   [2026-05 ▼] [当前批次 ▼]  数据准备中           │
│ 最后更新：2026-07-10 10:30             [继续处理] [更多 ▾]    │
├──────────────────────────────────────────────────────────────┤
│ 应收货款   综合支出   实际退款   利润   利润率   待处理异常     │
├──────────────────────────────────────────────────────────────┤
│ [报表概览] [异常核对 2] [数据准备]                            │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│                   当前 Tab 的主要内容                         │
│                                                              │
├──────────────────────────────────────────────────────────────┤
│ [展开运行日志与技术详情]                                      │
└──────────────────────────────────────────────────────────────┘
```

### 4.1 三个 Tab

#### Tab A：报表概览

用途：查看财务结果和店铺汇总。

默认进入条件：当前批次 `manifest.status === "final_ready"` 或 `manifest.final.status === "ready"`。

#### Tab B：异常核对

用途：集中查看马帮校验差异、店铺未匹配、订单未匹配和采集失败。

默认进入条件：存在阻断性校验失败，或当前批次需要人工处理且尚未生成。

#### Tab C：数据准备

用途：完成建批次、紫鸟数据、马帮数据、利润率配置和最终生成。

默认进入条件：无批次、正在采集、数据未就绪或等待生成。

### 4.2 Tab 默认选择规则

页面初始化后按以下优先级选择：

1. 无批次：`数据准备`。
2. 存在阻断错误：`异常核对`。
3. 报表已生成：`报表概览`。
4. 其他状态：`数据准备`。

用户手动切换 Tab 后，普通状态刷新不要强制抢回 Tab；只有选择其他批次或从“未生成”进入“已生成”时，才自动切换到合适 Tab。

## 5. 全局头部设计

### 5.1 标题区

显示：

- 页面标题：越南收支报表；
- 页面副标题；
- 当前月份；
- 当前批次状态；
- 最后更新时间；
- 若已生成，再显示最后生成时间。

### 5.2 月份与批次选择

月份选择器用于筛选历史批次。一个月份可能存在多个运行批次，因此月份后需要批次下拉框。

批次选项建议格式：

```text
2026-05-31 10:20 · 已生成 · 12 家店铺
2026-05-30 18:42 · 校验失败 · 12 家店铺
```

一期若尚未实现历史批次接口，可以只展示当前批次；但 HTML 结构和 JS state 应预留批次选择能力，不要把当前批次写死。

### 5.3 全局状态徽标

统一状态：

| UI 状态 | 显示文案 | 颜色 | 含义 |
| --- | --- | --- | --- |
| `empty` | 尚未创建 | 灰 | 没有批次 |
| `draft` | 等待数据 | 灰 | 已创建批次但未开始 |
| `running` | 处理中 | 蓝 | 任一任务运行中 |
| `needs_attention` | 需要处理 | 橙 | 存在非阻断配置或未匹配问题 |
| `blocked` | 已阻断 | 红 | 关键采集或校验失败 |
| `ready_to_generate` | 可以生成 | 绿 | 数据和配置已满足 |
| `generating` | 正在生成 | 蓝 | 最终文件处理中 |
| `ready` | 已生成 | 绿 | 文件已生成且无异常 |
| `ready_with_issues` | 已生成 · 有异常 | 橙 | 文件已生成但存在未匹配记录 |
| `failed` | 生成失败 | 红 | 最终处理失败 |

状态不能只通过颜色表达，必须同时使用文字和图标。

### 5.4 全局主操作

页面全局最多只有一个主按钮，按钮随状态变化：

| 当前条件 | 主按钮 | 点击行为 |
| --- | --- | --- |
| 无批次 | 创建报表批次 | 聚焦并提交基本设置 |
| 紫鸟补贴未完成 | 采集补贴订单 | 调用现有补贴 API |
| 紫鸟其余数据未完成 | 采集平台费用 | 调用现有广告/联盟/补贴 API |
| 马帮收支未完成 | 获取收支并校验 | 调用现有马帮收支 API |
| 马帮校验失败 | 重新导出并校验 | 重试现有马帮收支 API |
| 退款未完成 | 获取退款数据 | 调用现有退款 API |
| 缺少利润率 | 填写利润率 | 切换并定位利润率表 |
| 数据及配置完整 | 生成收支报表 | 调用最终生成 API |
| 任一任务运行中 | 查看处理进度 | 打开当前步骤和日志抽屉 |
| 已生成 | 打开 Excel 报表 | 调用 `open_path(output_file)` |
| 已生成但文件丢失 | 重新生成报表 | 定位生成步骤 |

禁用按钮下方必须显示原因，例如：

```text
还需完成：紫鸟广告消费（8/12 家）、联盟消费（10/12 家）
```

### 5.5 更多操作菜单

次要操作收进“更多”菜单：

- 新建批次；
- 重新生成；
- 打开 Excel 报表；
- 打开未匹配清单；
- 打开处理日志；
- 打开批次目录；
- 查看技术详情。

只展示当前状态真正可执行的操作，不保留“待接入”占位按钮。

## 6. 报表概览 Tab

### 6.1 KPI 卡片

已生成时展示 6 个指标：

1. 应收货款（调整后）；
2. 综合支出；
3. 实际退款；
4. 利润；
5. 利润率；
6. 待处理异常。

计算口径：

```text
综合支出 = 所有支出项 + 实际退款 + 实际联盟 + 最终广告花费
利润 = 调整后应收货款 - 综合支出
整体利润率 = 总利润 / 总调整后应收货款
```

注意：整体利润率不能简单平均店铺利润率。

格式要求：

- 金额统一使用 RMB；
- 显示千分位和两位小数；
- 真正的零显示 `¥0.00`；
- 缺失值显示 `—`；
- 负数使用负号和红色文字；
- 利润率统一显示百分比并保留两位小数。

未生成时不要展示一排 `—` 的财务卡片。改为展示轻量提示：

```text
报表尚未生成。完成数据准备后即可查看收支、利润和店铺汇总。
```

并提供“继续准备数据”按钮。

### 6.2 店铺汇总表

默认核心列：

| 列 | 数据字段 | 说明 |
| --- | --- | --- |
| 店铺名称 | `store_name` | 左侧冻结 |
| 订单数 | `order_count` | 数值 |
| 调整后应收 | `adjusted_receivable` | RMB |
| 综合支出 | `total_expense` | RMB |
| 实际退款 | `actual_refund` | RMB |
| 实际联盟 | `actual_affiliate` | RMB |
| 最终广告花费 | `final_ads` | RMB |
| 利润 | `profit` | RMB |
| 利润率 | `profit_rate` | 百分比 |
| 状态 | `status` | 正常/有异常 |

展开详情后显示：

- 匹配到的紫鸟店铺；
- 所有原始支出项；
- 调整后运费；
- 调整后包材费；
- 广告原值；
- 实际广告；
- 联盟原值；
- 广告补贴原值；
- 实际广告补贴。

表格行为：

1. 支持店铺名称搜索。
2. 支持状态筛选：全部、正常、有异常。
3. 支持“仅看异常”。
4. 支持对收入、支出、利润、利润率做数值排序。
5. 默认异常行优先。
6. 表头和店铺列滚动时保持可见。
7. 底部显示总计行。
8. 无筛选结果时显示“未找到符合条件的店铺”，并提供“清除筛选”。
9. 金额必须按数值排序，不能按格式化后的字符串排序。

### 6.3 结果文件区

显示：

- Excel 文件名；
- 生成时间；
- 平均汇率；
- 处理店铺数；
- 收支明细行数；
- 退款行数；
- 未匹配数。

操作：

- 打开 Excel 报表；
- 打开未匹配 CSV；
- 打开处理日志；
- 打开输出目录；
- 重新生成。

如果文件不存在，显示持久错误：

```text
报表文件已被移动或删除，请重新生成。
```

不要静默失败，也不要把“打开文件”错误只放入 Toast。

## 7. 异常核对 Tab

### 7.1 异常类型

统一归类为：

| 类型 | 数据来源 | 严重程度 |
| --- | --- | --- |
| 马帮收支校验差异 | `mabang.validation` | 阻断 |
| 紫鸟店铺未匹配马帮店铺 | `unmatched_rows` | 需处理 |

| 马帮数据采集失败 | `mabang.reports[]` | 阻断 |
| 缺少利润率 | 页面配置校验 | 阻断生成 |
| 最终文件生成失败 | `manifest.final` 或任务结果 | 阻断 |

- 阻断项数量；

| --- | --- |

| 来源 | 紫鸟/马帮/最终处理 |
| 店铺 | 可为空 |

### 7.4 马帮校验失败专用卡片

## 11. 响应式与视觉规范

### 11.1 视觉原则

1. 延续现有应用的蓝色主色和卡片体系，不做全局品牌重构。
2. 同一页面只使用一种主按钮颜色。
3. 减少卡片套卡片和大面积说明色块。
4. 金额数字使用等宽或表格数字特性，便于纵向比较。
5. 状态颜色统一：灰、蓝、绿、橙、红。
6. 所有状态同时显示图标和文字，不只依赖颜色。

### 11.2 桌面宽度

- `>= 1440px`：KPI 单行，筛选与主操作保持首屏可见。
- `1024px - 1439px`：KPI 2 至 3 列，筛选区换行，步骤内容单列。
- `< 1024px`：主操作保持明显，财务表横向滚动。
- `< 768px`：表单和 KPI 单列或双列，主按钮占满可用宽度，次操作收进更多菜单。

财务表格在窄屏必须横向滚动，店铺列保持冻结；不能强行压缩金额或产生页面级双横向滚动。

### 11.3 加载状态

1. 报表 KPI 和表格使用固定高度骨架屏。
2. 骨架屏不清除已存在的数据。
3. 骨架元素对读屏隐藏，同时提供“正在加载报表”的文本状态。
4. 用户点击后 300ms 内必须出现加载反馈。

### 11.4 可访问性

1. 页面只有一个 `h1`，标题层级连续。
2. Tab 使用 `role="tablist"`、`role="tab"`、`role="tabpanel"`。
3. Tab 支持键盘左右方向键切换。
4. 表单控件必须有可点击的 label。
5. 行内错误通过 `aria-describedby` 关联输入框。
6. 阻断错误区域使用 `role="alert"`。
7. 进度变化区域使用 `aria-live="polite"`。
8. 所有图标按钮必须有可读名称。
9. 焦点样式清晰，颜色对比满足 WCAG AA。
10. Tooltip 不能作为唯一错误提示或禁用原因。

### 12.3 总计计算要求

对店铺汇总行做 Decimal 计算，不使用 float：

```text
total.adjusted_receivable = sum(store.adjusted_receivable)
total.all_expense = sum(store.all_expense)
total.actual_refund = sum(store.actual_refund)
total.actual_affiliate = sum(store.actual_affiliate)
total.final_ads = sum(store.final_ads)
total.total_expense = all_expense + actual_refund + actual_affiliate + final_ads
total.profit = adjusted_receivable - total_expense
total.profit_rate = profit / adjusted_receivable（收入为 0 时返回 0）
```

6. 同一月份多个批次都要保留。

#### API 3：保存报表配置

```python
def save_vietnam_report_config(self, payload: dict[str, Any]) -> dict[str, Any]:
    ...
```

请求：

```json
{
  "manifest_path": "D:\\...\\manifest.json",
  "profit_rates": {
    "张三-越南001": "0.125",
    "李四-越南002": "-0.03"
  }
}
```

保存到 manifest：

```json
{
  "config": {
    "profit_rates": {
      "张三-越南001": "0.125"
    },
    "updated_at": "2026-07-10 10:10:00"
  }
}
```

要求：

1. 使用现有 `parse_profit_rate()` 校验并归一化。
2. 使用现有原子写 manifest 逻辑。
3. 保存配置不改变数据采集状态。
4. 历史 manifest 没有 `config` 时自动创建。
5. 最终生成仍兼容 `profit_rates_text`；前端提交前将保存后的 map 序列化为文本。

未匹配 CSV 可能很大，不要把全量记录塞入 Dashboard 或一次性渲染。

2. 只能读取当前 manifest 指向的未匹配文件，不能接受前端传入任意 CSV 路径。
3. Dashboard 只返回异常摘要和最多 20 条预览记录。
4. 筛选条件在后端执行；大文件不能全量返回给前端后再筛选。
5. 如果暂不实现“导出当前筛选结果”，界面只提供打开原始未匹配 CSV，不展示虚假的导出按钮。

### 12.7 利润率所需店铺提取

2. 没有退款店铺时返回空数组。
3. 空数组意味着不需要利润率，不能阻断生成。
4. 不要用紫鸟店铺清单替代退款店铺清单，否则会产生不必要的必填项。

### 12.8 文件存在性

```json

    "output_file": "D:\\...\\report.xlsx",
    "output_exists": true,
    "unmatched_file": "D:\\...\\unmatched.csv",
    "unmatched_exists": true
  }
}
```

路径仍以 manifest 的 run directory 为基准解析，必须防止相对路径误解析到当前工作目录。

### 12.9 Manifest 状态修复与并发保护

现有服务在发现文件已经完成后可能直接 skip，但未必同步修复根 `manifest.status`。最终生成又会检查根状态，可能出现“文件都齐了但永远无法生成”的历史批次。

建议新增纯函数：

```python
def derive_vietnam_manifest_status(manifest_path: Path, manifest: dict[str, Any]) -> str:
    ...

def reconcile_vietnam_manifest_status(manifest_path: Path, manifest: dict[str, Any]) -> bool:
    ...
```

要求：

1. readiness 以真实 report 状态、文件存在性和 `mabang.validation.status` 推导，不只信根 status。
2. `success` 只有在对应文件仍存在时才算完成；`no_data` 算完成。
3. 普通页面读取只返回 `derived_status`，不要因为“打开页面”就自动回写旧 manifest。
4. skip 分支、任务成功结束和最终生成校验前可以调用 reconcile。
5. 必要时提供显式修复 API，用于修复历史批次。

同一批次还需要后端互斥，不能只依赖前端禁用按钮。建议按 resolved manifest path 建立 run lock：

```text
同一 manifest 同一时间只允许一个写任务
```

冲突返回：

```json
{
  "ok": false,
  "error_code": "run_busy",
  "active_tool": "vietnam_mabang_income_collection",
  "error": "当前批次正在执行其他任务，请等待完成后重试。"
}
```

单进程至少使用 `RLock`；若需要支持多进程，再增加带 pid、tool 和 started_at 的 lock file，并处理 stale lock。可选增加 manifest `revision`，每次写入自增，前端轮询时丢弃旧快照。

### 13.4 任务恢复

当前页面只有：

```javascript
taskKey: "vietnam_subsidy_collection"
```

需要覆盖以下工具：

```javascript
const VIETNAM_TASK_KEYS = [
  "vietnam_subsidy_collection",
  "vietnam_ziniao_sources_collection",
  "vietnam_mabang_income_collection",
  "vietnam_mabang_refund_collection",
  "vietnam_final_reconciliation"
];
```

推荐扩展 `common.js` 支持：

```javascript
page.taskKeys = VIETNAM_TASK_KEYS;
```

恢复策略：

1. 分别调用 `get_latest_task_status(tool)`；
2. 优先选择状态为 `running` 或 `pending` 的最新任务；
3. 否则选择 `created_at` 最新的任务；
4. 恢复日志和任务进度；
5. 任务完成后刷新 manifest 和 Dashboard；
6. 若页面仍使用旧版 Bridge，捕获错误并降级为当前行为。

不要让本次公共逻辑改造影响其他模块现有单 taskKey 行为。

为避免“最新任务属于另一个批次”却被错误恢复，建议给 `TaskRecord` 增加向后兼容的可选 context：

```json
{
  "manifest_path": "D:\\...\\manifest.json",
  "run_id": "vn_202605_xxx",
  "stage": "mabang_income"
}
```

五个 start API 启动任务时传入 context。页面只恢复 context 与当前选中 manifest 一致的任务。

注意：当前 TaskManager 是内存任务管理器。它只能恢复当前应用进程内的任务，不能跨应用重启。跨重启恢复必须依赖“最后批次路径 + manifest”。如果 manifest 中存在 `running`，但当前进程没有对应 live task，view model 应显示“上次运行已中断，可重试”，不能永久显示采集中，也不要在页面加载时自动改写 manifest。

## 17. 各业务状态验收标准

### 17.1 无批次

- 默认打开“数据准备”。
- 不展示空财务 KPI、空马帮卡片和大块空日志。
- 显示单一空态和“创建报表批次”。
- 月份默认上个月并显示起止日期。
- 店铺去重和 200 家限制即时反馈。
- 缺少账号、月份、目录或店铺时，明确列出缺少项。
- 创建失败在表单内持久显示。
- 创建成功后冻结批次范围。

### 17.2 采集中

- 默认打开“数据准备”，自动展开当前步骤。
- 显示当前任务、开始时间和进度，例如“8/12 家”。
- 重复启动按钮禁用。
- 已完成数据保持显示，不因轮询清空。
- 后续步骤只显示锁定原因。
- 日志默认折叠，可展开和复制。
- 单项 `no_data` 显示“0 条（已完成）”。
- 单店失败保留其余成功结果，并显示失败店铺和原因。

### 17.3 校验失败

- 顶部显示持久红色阻断提示。
- 自动打开或明显引导到“异常核对”。
- 显示明细/汇总订单数、订单差异及应收差异。
- 店铺级差异默认异常优先。
- 主操作为“重新导出并校验”。
- 生成按钮不可执行，并显示阻断原因。
- 重试成功后阻断自动消失。

### 17.4 数据已就绪但缺配置

- 自动定位“配置并生成报表”。
- 展示已满足的所有前置项。
- 自动列出需要利润率的退款店铺。
- 支持 `12.5%`、`0.125` 和 `12.5`。
- 漏填和格式错误在对应行内提示。
- 显示“还缺 N 家店铺利润率”。
- 没有退款店铺时，不要求利润率。
- 主按钮禁用时显示具体原因。

### 17.5 可以生成

- 顶部状态为“可以生成”。
- 主操作为“生成收支报表”。
- 生成前提示会创建新版本、不覆盖原始文件。
- 生成中禁止重复提交并显示文件处理进度。
- 生成失败保留配置和已有数据。

### 17.6 已生成且无异常

- 默认打开“报表概览”。
- 显示生成时间、文件名、KPI 和店铺汇总。
- 状态为“已生成”。
- 异常 Tab 显示成功空态。
- 主操作为“打开 Excel 报表”。

### 17.7 已生成但有异常

- 默认打开“报表概览”。
- 状态为“已生成 · 有异常”，不能显示为完全正常。
- KPI 正常显示。
- 异常数使用橙色并可点击进入异常 Tab。
- 提供打开未匹配 CSV。
- 报表仍可打开；异常不是生成失败。

### 17.8 文件丢失

- manifest 显示已生成但文件不存在时，不把数值显示为 0。
- 固定提示“文件已不存在，请重新生成”。
- 主操作改为“重新生成报表”。
- 技术详情显示原记录路径。

### 17.9 页面刷新或重新进入

- 当前进程内存在匹配任务时，恢复任务状态和日志。
- 应用重启后以 manifest 恢复已完成进度，不依赖已失效 task id。
- manifest 留有 `running` 但没有 live task 时，显示“上次运行已中断”，不能永久显示处理中。
- 不自动重新启动任何任务。
- 用户已保存的利润率配置可以恢复。

## 21. 兼容性与数据安全

### 21.1 Manifest 是持久化事实来源

- manifest 保存批次、数据项、校验和结果文件状态。
- UI 的 current/completed/locked 等状态只在内存中推导，不另建一套持久化状态。
- TaskManager 只用于当前进程实时任务；应用重启后不能假设 task id 仍有效。
- 打开旧 manifest 时只在内存补默认值，不因“查看”自动改写历史文件。

### 21.2 路径规则

- manifest 内数据文件路径继续尽量使用相对 run directory 的路径。
- Bridge 响应可返回解析后的绝对路径。
- 不把绝对 manifest 路径放入 URL。
- 所有打开文件操作都从当前选中批次的 manifest 派生。
- 历史列表只扫描受控目录，不扫描整块磁盘。

### 21.3 原始文件只读

- 紫鸟及马帮原始 CSV/XLSX 不覆盖。
- 页面重试不能删除此前成功文件。
- 最终重新生成创建新版本。
- 历史生成记录应保留。

### 21.4 旧版本 Bridge 降级

如果新版前端运行在缺少新增 API 的旧 Bridge 上：

- 捕获“方法不存在”异常；
- 保留当前批次采集和生成流程；
- 概览显示“当前客户端版本暂不支持在线报表概览，请打开 Excel 查看”；
- 不能导致整个页面无法初始化。
