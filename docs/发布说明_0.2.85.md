# 0.2.85 发布说明

日期：2026-10-29。

## Lazada Balance 截图热修

本次处理 0.2.84 用户反馈的 Balance 截图尺寸漂移，以及店铺打开阶段的紫鸟 IP 检查问题。

- 截图前等待页面尺寸连续三次一致，再开始截图，减少页面异步加载造成的误报。
- 仅针对布局变化专用异常执行完整重拍，最多尝试三次。每次失败后退出本次截图流程、恢复临时布局，再重新准备页面和截图，不沿用上次未完成的布局状态。
- 金额、提现快照、页面与窗口身份校验继续保留。页面持续不稳定时明确报告失败，不保存可能裁剪或不完整的图片。

## 紫鸟 IP 检查等待

- IP 检查页面导航超时后，在同一检测 URL 和窗口 handle 中继续显式等待真实成功标记；导航超时本身不再立即作为检查失败，也不等同于检查通过。
- 未取得成功标记时仍不放行。检测页面缺失、等待超时或发生异常时，提供对应阶段的具体提示。
- 此修改解决导航超时导致的误判；真实代理线路异常仍会报告失败。检测等待结束后未取得通过标记的店铺，需要检查代理线路和检测页面。

## 保留的导出格式

仅导出一张「余额统计」工作表，列顺序仍为店铺名称、Income、Income截图、Balance、Balance截图、Ads、Ads截图、processing、processing截图、站点、币种、状态、采集时间和说明。四张图片直接嵌入 C/E/G/I 列，每项金额后紧跟对应截图；截图单元格只放图片，按比例缩小至最大 320×200 像素展示。

Balance 仍保存包含当前页提现记录的完整页面截图。最新提现成功或确认无提现记录时，processing 金额留空，仍须保存对应状态截图。金额及提现状态口径不变。详见 [余额统计使用说明](balance-statistics.md)。

## 验证与构建来源

本次为当前工作区热修候选包。已用本地真实浏览器复现旧版尺寸变化错误，并验证稳定页面、一次变化、两次变化、processing 全页截图、持续变化和窗口身份变化六种情形。真实店铺的 CLI 诊断范围、最终回归结果、冻结程序自检、构建来源和文件哈希以同版本构建清单及验证报告为准。

本次按用户反馈修复并打包当前工作区，没有拉取桌面上游、创建 Git 合并提交或公开推送。桌面权威上游仍为 `https://github.com/yyl152765/hqyl_desktop.git` 的 `main`，父工作区提交单独记录。已有 TEMU 修复、Lazada 受限账单流程和钉钉配置等工作保留。

共享依赖沿用 0.2.84 已核验的构建基线，0.2.85 构建输入位于 `build/release_inputs_0.2.85`。本次仅生成本地未签名 Windows 安装包及服务器上传包，不执行安装、上传或远程发布；0.2.84 文档与旧版本产物保留。
