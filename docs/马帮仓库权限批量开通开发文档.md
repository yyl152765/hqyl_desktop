# 马帮仓库权限批量开通开发文档

## 1. 背景与目标

当前马帮 ERP 的仓库权限需要管理员逐个搜索员工、进入数据权限页面，依次完成“查看商品”“查看订单”和“查看仓库”中的仓库勾选，再回到商品父目录排除 EB 产品并保存。员工数量较多时，重复操作耗时且容易漏选。

本功能接入寰球云联自动化平台，支持批量输入员工姓名，为唯一匹配的员工批量新增指定仓库的数据权限，并输出逐员工处理结果。

第一版保留员工已有仓库，不修改岗位、角色、部门和店铺权限；同时严格按用户操作文档同步商品查看方式、商品父目录和商品父目录/仓库联动字段。

## 2. 已确认的马帮接口

测试环境：`https://900853.private.mabangerp.com`

### 2.1 员工搜索

- 页面：`/index.php?mod=employee.list`
- iframe 页面：`https://private-amz.mabangerp.com/index.php?mod=staff.list`
- 接口：`POST https://private-amz.mabangerp.com/index.php?mod=staff.getEmployList`
- 关键参数：
  - `search-content=nameLike`
  - `searchtext=<员工姓名>`
  - `status=1`
  - `page=1`
  - `rowsPerPage=100`
- 返回：JSON，其中 `html` 为员工列表 HTML。
- 员工详情链接包含员工 ID，例如 `mod=staff.staffdetail&id=1117519`。

员工匹配规则：

1. 对输入姓名做首尾空白清理和去重。
2. 只接受员工列表中姓名文本完全相等的记录。
3. 完全匹配为 0 条时标记“未找到”。
4. 完全匹配超过 1 条时标记“同名待确认”，第一版不自动保存。
5. 唯一匹配时记录员工 ID、姓名、手机号、部门和状态。

### 2.2 员工数据权限详情

- 外层页面：`/index.php?mod=staff.staffdetail&id=<员工ID>&channel_id=1&isDetail=2`
- iframe 页面：`https://private-amz.mabangerp.com/index.php?mod=staff.staffdetail&id=<员工ID>&isDetail=2`
- 仓库查看方式字段：`see_warehouse`
  - `1`：查看指定仓库
  - `2`：查看全部仓库
- “查看仓库 → 查看指定仓库”的启用仓库字段：`allocationwarehouseAssistant[]`
- “查看商品 → 库存 SKU → 按仓库查看”的仓库字段：`stockWarehouse[]`
- 订单查看方式字段：`comboType`，本功能设置为 `2`（按仓库查看）。
- “查看订单 → 按仓库查看”的仓库字段：`warehouseAssistant[]`。
- 商品查看方式字段：`stockCategoryOrWarehouse`
  - `1`：按商品父目录查看
  - `2`：按仓库查看
- 商品父目录字段：`stockCategory[]`
- 商品父目录与仓库联动字段：`parent_category_and_warehouse=1`
- `EB 产品` 父目录 ID：`1696862`，保存时必须取消勾选。
- 仓库字段值为仓库 ID，页面标签文本为仓库名称。

仓库列表从员工详情页读取，不在本地维护固定配置，避免马帮新增、改名或停用仓库后出现配置漂移。

### 2.3 保存员工权限

- 接口：`POST https://private-amz.mabangerp.com/index.php?mod=staff.doUpdateEmployee&id=<员工ID>`
- 请求体：`formData=<Base64(完整员工表单 URL 编码结果)>`
- 返回：JSON，`success=true` 表示保存成功。

马帮保存接口提交整张员工表单。根据用户提供的《添加仓库》操作文档，实现必须读取原详情页的所有有效表单控件，保持无关字段原值，并且只修改用户本次选择的权限类型：

1. 选择“查看仓库”时保持员工原有 `see_warehouse` 查看方式；“查看全部仓库”只补目标复选框，不缩小已有权限范围。
2. “查看商品”“查看订单”“查看仓库”可独立多选，默认三项全选，至少选择一项。
3. 只对选中的权限，将目标仓库 ID 与对应的 `stockWarehouse[]`、`warehouseAssistant[]` 或 `allocationwarehouseAssistant[]` 做并集合并；未选权限保持原表单值。
4. 预览只计算所选权限的缺失仓库；所选权限任意一侧缺失，或所选“查看订单”不是按仓库查看，都进入保存任务。
5. 选择“查看商品”时，设置 `stockCategoryOrWarehouse=1`，切回“按商品父目录查看”。
6. 选择“查看商品”时，设置 `parent_category_and_warehouse=1`，并勾选全部 `stockCategory[]`，但排除 `EB 产品`（ID `1696862`）。
7. 保留其他字段和值；以 UTF-8 URL 编码后执行标准 Base64 编码。
8. 每名员工只提交一次保存；选择“查看商品”时使用最终商品父目录状态提交。
9. 保存后重新读取详情页，只校验本次选中的权限；任意所选权限未生效都判定失败。

## 3. 页面设计

新增页面：`马帮仓库权限批量开通`

页面分为五个工作区：

1. 账号栏：显示当前绑定的马帮账号，可跳转账号管理。
2. 权限选择：查看商品、查看订单、查看仓库三个复选项，默认全部勾选，至少选择一项。
3. 员工输入：多行文本框，一行一个员工姓名，实时显示去重后数量。
4. 仓库选择：从马帮动态加载仓库；提供名称搜索、全选当前筛选结果、清空选择和已选数量。
5. 预览与执行结果：表格展示员工、匹配状态、手机号/部门、三类权限差异、处理结果和错误信息。

页面操作：

- `加载仓库`：登录马帮并读取最新仓库列表。
- `预览检查`：搜索员工并读取唯一匹配员工的当前仓库权限，不保存。
- `开始开通`：只处理最近一次预览中“可开通”且数据未变化的员工。
- `复制日志`：复用现有日志组件。

开始开通前必须完成预览。员工输入、权限选择、仓库选择或账号发生变化后，旧预览立即失效，防止将过期预览用于保存。

## 4. 后端设计

新增服务模块：`backend/services/mabang_warehouse_permission.py`

马帮的 `private-amz` 员工接口会绑定浏览器运行时会话，普通 HTTP 客户端即使登录成功也会被重定向。服务使用 Playwright 启动隔离的无界面 Chrome，在马帮页面上下文中完成登录、员工查询和权限保存；不读取用户现有 Chrome 的 Cookie，也不向前端暴露浏览器会话。

核心数据结构：

- `MabangWarehouse`：仓库 ID、名称。
- `MabangEmployeeMatch`：员工 ID、姓名、手机号、部门、状态、详情地址。
- `EmployeePermissionPreview`：匹配状态、原有仓库、待新增仓库、是否可执行。
- `WarehousePermissionJob`：账号、员工列表、目标仓库 ID、预览签名。
- `WarehousePermissionBatchResult`：成功、跳过、失败、待确认数量及逐员工结果。

桥接接口：

- `get_mabang_warehouse_options(payload)`：返回动态仓库列表。
- `preview_mabang_warehouse_permissions(payload)`：返回员工匹配和权限预览。
- `start_mabang_warehouse_permission_batch(payload)`：启动后台保存任务。

执行流程：

1. 使用当前绑定马帮账号登录一次。
2. 对员工姓名顺序查询并精确匹配。
3. 获取唯一匹配员工的权限详情。
4. 只比较本次选中的仓库权限、订单查看方式或商品父目录状态；所选项全部符合才跳过。
5. 校验员工、仓库和权限类型是否与预览一致；任一变化则拒绝保存。
6. 只合并所选权限对应的仓库 ID；按需设置订单模式或商品父目录规则，提交完整表单。
7. 重新获取详情页，只验证本次选中的权限。
8. 单员工失败时记录错误并继续处理后续员工。

## 5. 数据保护与错误处理

- 密码仅从本地绑定账号读取，不返回前端、不写日志。
- 日志不输出完整请求表单、Cookie、密码或 Base64 表单内容。
- 默认串行执行，降低马帮会话过期、限流及覆盖写入风险。
- 员工已有“查看全部仓库”权限时不改为“查看指定仓库”，避免权限降级。
- 每位员工保存前重新读取详情，避免使用旧权限快照覆盖他人刚完成的修改。
- 同名员工不猜测、不自动选择。
- 保存结果必须通过二次读取校验，接口返回成功但校验失败仍按失败处理。
- 马帮登录失效、页面结构变化、缺少关键字段时立即给出明确错误。
- 批次结果保留员工级状态，便于人工重试失败项。

## 6. 测试范围

### 6.1 服务单元测试

- 员工姓名清理、去重和上限校验。
- 员工列表 HTML 解析：唯一匹配、未找到、同名。
- 仓库列表及已选仓库解析。
- HTML 表单成功控件序列化。
- `see_warehouse` 替换和 `allocationwarehouseAssistant[]` 并集合并。
- `stockWarehouse[]`、`warehouseAssistant[]` 与 `allocationwarehouseAssistant[]` 同步并集合并。
- `comboType=2`，将查看订单切换为按仓库查看，同时保留原有订单仓库。
- `stockCategoryOrWarehouse=1`、父目录联动启用、全选非 EB 商品父目录。
- 单选或多选权限时只修改所选权限，未选权限保持原值。
- 空权限选择和未知权限类型校验。
- 保存后二次校验三组仓库、订单查看方式与商品父目录最终状态。
- Base64 请求体编码。
- 预览签名稳定性与变化检测。
- 单员工失败后继续批次。
- 保存后二次校验失败。

### 6.2 桥接与前端测试

- 未绑定马帮账号时返回绑定提示。
- 页面脚本引用的 DOM ID 全部存在。
- 新页面加入侧边栏、预览 API 和前端完整性检查。
- JavaScript 语法检查。

### 6.3 人工验收

1. 使用测试员工加载仓库并完成预览。
2. 选择一个测试仓库执行开通。
3. 分别仅选择“查看商品”“查看订单”“查看仓库”执行，确认只修改所选权限。
4. 三项全选执行，确认三处仓库均已启用，且查看订单为按仓库查看。
5. 选择“查看商品”时，确认商品查看方式为“按商品父目录查看”，父目录除 EB 产品外全部勾选。
6. 再次执行相同批次，结果应为“无需新增”，不得重复修改其他权限。
7. 输入不存在姓名和同名员工，确认不会保存。

## 8. 第一版不包含

- 批量移除仓库权限。
- 修改员工岗位、角色、部门、店铺权限或文档未指定的其他数据权限。
- 自动处理同名员工。
- 并发保存员工权限。
- 将马帮仓库 ID 固化到本地配置。
