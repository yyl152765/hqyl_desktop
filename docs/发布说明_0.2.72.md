# 0.2.72 发布说明

日期：2026-10-14。

本次修复 BigSeller 批量 SKU 查询触发频率限制后连续失败的问题。服务端可能返回 HTTP 200、业务错误码 `-1`，提示 `The request is too frequent. Please try again later`。旧商品 ID 查询没有成功请求间隔，也没有识别这条英文限流提示，导致失败后继续请求下一 SKU。0.2.71 增加错误码提示，0.2.72 增加实际的请求节流与限流恢复。

## 修复内容

- 商品 ID 查询增加进程内请求锁，按 0.75 秒目标间隔串行发送；遇到限流登记共享冷却时间，并重试当前 SKU。
- 响应解析识别中文频繁、限流，以及英文 `too frequent`、`too many`、`rate limit`；登录失效和权限不足优先分类，原始服务端消息不写入运行日志。
- 商品 ID 查询每个 SKU 最多请求 3 次；未提供有效 `Retry-After` 时按 10、20 秒等待。服务要求等待超过 30 秒或重试耗尽时停止后续查询，保留所有输入 SKU，任务标记“结果不完整”。
- 滞销 SKU 爆款对标共用限流解析，在请求锁内识别并登记至少 10 秒限流冷却，避免另一并发任务赶在冷却登记前继续请求；限流等待从 10 秒开始，需要等待 40 秒时保存进度并交下一轮补查。

搜索仍为 SKU（含子 SKU）模糊查询、Shopee 在售商品、当前账号全部可访问店铺；商品 ID 导出仍只有 SKU 和 Item ID 两列。
