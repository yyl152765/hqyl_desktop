# 自动更新方案

## 1. 目标

用户安装一次客户端后，后续更新不再依赖人工发送安装包。客户端启动或用户点击更新中心时，自动读取远程发布清单，提示或执行更新。

## 2. 推荐分层

### 前端界面更新

适合只改页面、样式、文案、表单布局的版本。发布方式：

1. 构建前端包。
2. 上传到公司 OSS、内网 HTTP 服务或 GitHub Release。
3. 更新 `latest.json` 中的 `frontend_url` 和 `version`。
4. 客户端检查清单后下载并替换本地前端资源。

### 客户端完整更新

适合 Python 后端逻辑、依赖、打包配置变化的版本。发布方式：

1. 构建 `HQYLAutomationSetup_x.y.z.exe`。
2. 上传安装包。
3. 更新 `latest.json` 中的 `package_url` 和 `version`。
4. 客户端检查到新版本后下载安装包并启动安装。

## 3. 发布清单格式

```json
{
  "version": "0.2.1",
  "mandatory": false,
  "notes": "优化 SKU 采购日志界面，修复导出目录选择问题。",
  "frontend_url": "https://example.com/hqyl/frontend_0.2.1.zip",
  "package_url": "https://example.com/hqyl/HQYLAutomationSetup_0.2.1.exe",
  "sha256": ""
}
```

当前代码已实现：

- 保存更新源地址。
- 检查远程 `latest.json`。
- 比较当前版本与最新版本。
- 在界面展示更新状态。

后续要补的能力：

- 下载前端包或安装包。
- 校验 SHA256。
- 用独立 updater 进程替换正在运行的文件。
- 支持灰度发布和强制更新。

## 4. 为什么不只靠安装包

安装包适合首次安装和底层依赖升级，但不适合频繁 UI 调整。寰球云联平台以后会持续接入马帮、紫鸟、店小秘、BigSeller 等流程，建议保留两层更新：

- 页面资源可以小步快跑。
- 后端能力按稳定版本发布。
