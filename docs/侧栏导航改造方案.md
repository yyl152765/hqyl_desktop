# 侧栏导航改造方案

日期：2026-09-05

状态：源码改造已完成，69 项自动测试通过；真实 pywebview 关闭重启及系统输入法人工验收尚未执行。本次不生成安装包、不调整应用版本。

## 1. 问题与目标

现有侧栏由 `frontend/assets/common.js` 的 `renderSidebar()` 统一生成，样式位于 `frontend/assets/app.css`。业务页面通过独立 HTML 链接切换，共有 17 个业务模块，另有工作台和设置。

改造前的模块行至少 54px，名称下方固定显示说明；国家、平台、采购、仓库等副标题另占一行，并叠加分隔线、卡片间距和分组英文说明。所有组持续展开，使可见入口偏少。工作台和设置也在同一滚动区域内，寻找底部模块和设置需要较长滚动。侧栏的 600px 最小高度还会影响矮窗口下的入口可达性。

本轮目标是减少导航占用的纵向空间，让用户能够通过原有分组、搜索和个人常用入口迅速找到模块。保留既有模块名称、链接和主分组，降低迁移成本。更改导航不应改变业务表单、任务执行、日志和页面切换后的任务恢复。

## 2. 本轮范围

- 菜单使用 36–40px 单行布局，保留图标、名称和必要短标签；完整说明通过悬停提示展示。
- 保留财务流程、马帮流程、紫鸟流程、EchoTik、BigSeller 五个现有主分组及组内顺序，增加折叠和模块数量。
- 顶部固定模块搜索和工作台入口；常用入口置于中间列表顶部；设置、版本和任务状态固定在底部。
- 支持搜索全部业务模块、设置个人常用、跨页面及应用重启保存导航偏好。
- 建立单一导航元数据，供分组、搜索和常用视图共同使用。
- 仅新增保存 UI 偏好的桥接 API；不改业务 API、账号配置、业务脚本、任务运行或恢复逻辑。

本轮不重新按财务、采购、仓库等业务归类，不增加最近访问、推荐模块、云端同步、拖拽排序或业务功能。

## 4. 布局与交互约定

### 4.1 固定区与滚动区

```text
品牌
搜索模块                         Ctrl+K
工作台
─────────────────────────────────────
常用模块                         0/5
  用户加入的模块，按加入顺序显示

财务流程                         1  ▸
马帮流程                         9  ▾
  模块图标  模块名称  短标签         ☆
紫鸟流程                         3  ▸
EchoTik                          1  ▸
BigSeller                        3  ▸
      ↑ 仅此中间列表区域滚动 ↑
─────────────────────────────────────
设置
当前版本 / 更新或任务状态
```

常用放在中间列表顶部，避免加入 5 个常用后压缩掉全部分组的可用空间。桌面侧栏使用固定高度、可收缩的中间区域，移除原 600px 最小高度造成的溢出。矮窗口下缩减品牌、间距和状态区的装饰性空间，保持搜索、工作台、设置以及中间列表可达。窄屏沿用页面响应式能力，不生成覆盖业务内容的浮层。

普通模块行高 36–40px，名称单行显示；过长名称可省略，但完整名称、旧分组路径及说明必须可通过提示获取。行内标签只保留辨识所需的短内容，如“越南”“TikTok”“采购”，不挤压名称或强制换行。搜索结果需要展示完整归属路径，可以使用额外的紧凑路径行。

已落地的桌面侧栏宽度为 **296px**，普通模块整行高度 **38px**；模块名称及分组标题使用 **13px** 字号，短标签 **10px**，搜索结果路径 **11px**。名称的可读性通过压缩重复说明和留白保留，不依赖缩小主文字。

### 4.2 分组折叠

- 分组标题使用可键盘操作的按钮，显示名称、业务模块总数及展开状态。
- 首次进入业务页，默认展开当前模块所在组；首次进入工作台或设置，没有对应业务组时可以全部收起。
- 允许同时展开多个分组，不采用只能打开一个分组的手风琴限制。
- 读取已保存的展开组，进入业务页时保证当前模块所在组展开；其他组沿用用户选择。用户仍可在当前页手动收起该组。
- 点击模块后保留既有页面跳转方式，当前入口有清晰高亮及 `aria-current="page"`。
- 折叠只隐藏该组列表，不移除模块，也不影响搜索命中或常用入口。

### 4.3 搜索

- 搜索框固定在侧栏顶部，输入时即时筛选全部 17 个业务模块；不向后端发起业务查询。
- 搜索范围包括模块名称、说明、平台、国家、所属系统、主分组、旧副标题及必要别名。比如“寄样”“TikTok”“菲律宾 Shopee”“紫鸟 马帮”“采购流程”都能沿原有信息找到入口。
- 英文大小写不敏感，忽略首尾空白，按一个或多个空白拆分关键词，所有关键词均匹配才命中（AND）。关键词可以分别命中同一模块的不同字段。
- 结果按原导航顺序排列，同一模块只显示一次；每项显示名称和原分组路径，避免“收支报表”等相似名称难以区分。
- 搜索期间展示结果列表，不受分组折叠影响，也不修改保存的展开状态。清空搜索后恢复原常用及分组视图。
- `Ctrl+K` 聚焦搜索；`Escape` 清空搜索；搜索框内按 `Enter` 打开第一条结果；无结果时不跳转。
- 中文输入法组合输入期间不得把确认候选词的 `Enter` 当成导航操作；组合输入状态也不得触发清空或快捷跳转。
- 无命中时显示明确空态，允许直接修改或清空关键词。结果数量和空态通过适当的无障碍提示告知。

### 4.4 个人常用

- 每个业务模块旁提供星标按钮，支持加入和移出常用；点击星标不跳转模块页面。
- 最多 5 个，无预置项，不根据猜测替用户添加。
- 常用按用户加入顺序排列；移除后再加入排在末尾。
- 第 6 次加入时保留现有 5 项并给出“最多可添加 5 个常用模块，请先移除一项”等清晰提示。
- 在分组、常用和搜索结果中操作同一模块的星标，所有视图立即保持一致。
- 星标按钮具有明确的加入/移出文案、`aria-pressed` 和可见键盘焦点；不把按钮嵌套在页面链接内。

### 4.5 保留既有状态能力

保留版本元素 `appVersion`、状态元素 `updateSummary` 的 ID 与更新入口。现有 `renderGlobalTaskStatus()`、账号状态、业务任务轮询及最近任务恢复继续使用原逻辑。设置固定在底部，工作台固定在顶部。

## 5. 实现与持久化设计

### 5.1 单一导航元数据

在共享导航代码中声明五个主分组及 17 个模块的元数据，包含稳定页面 ID、链接、名称、图标、说明、旧副标题、短标签和搜索别名。分组、常用、搜索结果从同一份数据生成，避免三份手写列表发生遗漏或名称不一致。

后续增加模块时必须同步提供所属组和搜索字段，数量由元数据计算。渲染字符串或属性时正确转义文本；查询词按普通文本处理，不解释为 HTML 或正则表达式。

### 5.2 桌面持久化

项目使用 pywebview 桌面壳。当前启动代码未指定 `private_mode`，本机安装的 pywebview 默认启用私密模式，不能仅依赖 localStorage 承诺应用重启后仍保留偏好。

因此桌面偏好写入独立文件：

```text
%APPDATA%\HQYLAutomation\sidebar.json
```

新增两个只服务导航偏好的桥接方法：

- `get_sidebar_preferences()`：返回 `{ok: true, preferences: 对象或null}`；文件缺失、内容损坏或版本不受支持时返回 `null`，交由前端使用缓存或默认状态，不重写损坏的原文件。
- `save_sidebar_preferences(preferences)`：校验并保存常用和展开组，成功返回 `{ok: true, preferences: 校验后的对象}`；输入或读写错误返回 `{ok: false, error: 提示}`，不触发账号或业务配置写入。

桥接收发的偏好对象如下，字段保存稳定 ID：

```json
{
  "favorites": ["sample_registration", "sku_inventory_query"],
  "expandedGroups": ["mabang"]
}
```

磁盘文件使用版本包裹，便于后续迁移：

```json
{
  "schema_version": 1,
  "preferences": {
    "favorites": ["sample_registration", "sku_inventory_query"],
    "expandedGroups": ["mabang"]
  }
}
```

后端校验对象及字段类型，只接受 1–80 位字母、数字、下划线或短横线组成的 ID；字符串列表去重并保留顺序，常用最多 5 个、存储层展开组最多 32 个，非法或超额输入不会覆盖已保存数据。当前前端进一步限制为已定义的五个组和 17 个模块，过滤未知或已删除的 ID。

写入采用进程锁、同目录临时文件、刷新落盘及原子替换；替换失败时保留原文件并清理临时文件。实现位于 [backend/sidebar_preferences.py](../backend/sidebar_preferences.py)，由 [backend/app_bridge.py](../backend/app_bridge.py) 暴露偏好桥接。导航偏好不写入账号所用 `settings.json`，不改变桌面壳隐私设置。

星标和折叠立即更新界面，保存按顺序排队。点击模块、工作台或设置后，会等待已开始的偏好读取及写入队列稳定，再离开当前页面；等待期间发生的新操作也会纳入保存，避免页面卸载丢失最后一次选择。正常加载时以桌面桥接返回的数据为持久化基线。

### 5.3 浏览器预览与安全降级

普通浏览器预览使用 localStorage 键 `hqyl.sidebar.v1`，保存偏好及临时操作日志：

```json
{
  "favorites": ["sample_registration"],
  "expandedGroups": ["mabang"],
  "pendingOperations": [
    {"type": "favorite", "id": "sample_registration", "enabled": true}
  ]
}
```

`pendingOperations` 用于按完整顺序记录桌面桥接就绪前的操作，类型为 `favorite`、`group` 或 `collapseAll`。不能只保留每个 ID 的最后一次操作，否则满 5 个常用时“移除→新增→移除→重加”的顺序和容量判断可能改变。在桥接尚未就绪时切换页面，这些记录随缓存保留；桥接返回磁盘基线后按操作意图回放增删和折叠，再补存并清空临时日志。这样既保留用户刚做的操作，也不会用尚未加载完整的常用列表覆盖旧常用。若回放新增时原常用已满 5 个，保留原常用并提示用户先取消一项。

携带待回放操作进入另一个业务页时，还会追加当前组的展开意图，确保新页面初始显示当前模块；在当前页面主动收起该组的操作仍会被尊重。

桌面桥接不可用时，可使用该缓存及当前页面内存作为降级，但不能把私密模式下的 localStorage 等同于可靠的跨应用重启保存。`pendingOperations` 不写入桌面偏好文件。

- 文件或键不存在：常用为空，按当前页决定默认展开组。
- JSON 损坏、字段类型错误、未知 ID、重复 ID、超额常用：使用经校验的数据或默认值，页面仍可正常导航。
- 文件读写失败、localStorage 不可读写：当前页面内交互继续工作；不能向用户误报已持久保存。
- 搜索文本仅保存在当前页面，不写入偏好文件。

## 6. 验收标准

1. 全部 17 个业务模块的名称、页面 ID、链接和所属主分组保留，分组数量分别为 1、9、3、1、3，无遗漏或重复入口元数据。
2. 普通模块行高在 36–40px 内；副标题和说明不再单独长期占用整行；长名称、说明及原路径可查看。
3. 当前模块正确高亮；首次进入业务页能看到所在组；允许多组展开；切换页面及重启桌面后恢复有效的常用和展开偏好。
4. 搜索可按名称、说明、平台、国家、系统和旧分组命中；英文大小写和多余空白不影响结果；多个关键词采用 AND。
5. 搜索结果展示归属路径，不受收起的组影响；清空后恢复分组状态；无命中不会产生错误或跳转。
6. `Ctrl+K`、`Escape`、`Enter` 按约定工作；中文输入法确认候选词不会误跳转。
7. 常用初始为空，可增删并按加入顺序保存，最多 5 个；第 6 个被拒绝且有提示；星标操作不导航。
8. 顶部搜索和工作台、底部设置及版本/任务状态在桌面常用尺寸和矮窗口下仍可达；中间列表单独滚动；不存在入口被底部遮住的情况。
9. 存储缺失、损坏、类型异常或不可用时导航仍正常；未知 ID 不生成错误链接；异步加载、快速连续操作不回退到旧偏好。
10. 既有业务表单、账号能力、页面跳转后最近任务/日志恢复不受影响；没有新增业务任务或真实平台写操作。

- 缓存 JSON 损坏、类型错误、未知或重复 ID、存储读写被禁止时，导航仍可使用。
- 原生偏好晚到时保留旧常用并回放新增操作，尊重用户刚收起的组；桥接就绪前操作跨页后仍可合并补存。
- 已有 5 个常用时连续移除、新增、再次移除和重加，回放后保持用户操作顺序；同时覆盖原生返回完整基线及 `null` 两种情况。
- 快速连续操作按序保存；点击导航后等待保存时再收藏，也必须等新保存完成后离页。
- 980×640 和 1180×760 下，5 个常用及全部组展开时普通行保持 36–40px，只有中间列表滚动，搜索和设置可点击且未被遮挡。
