## 使用入口

- 桌面侧栏：紫鸟流程 → 在售商品导出。
- 工作台：TEMU 在售商品导出。
- 开发启动：`.\.venv\Scripts\python.exe desktop_entry.py --page=temu-on-sale-export`。

运行电脑需安装紫鸟客户端，并在平台「设置 → 紫鸟账号」绑定及选中公司、账号和密码。客户端路径和驱动目录与广告充值复用同一自动发现函数，也可在页面手动选择。后台只接受账号 ID，再从平台配置读取凭据，忽略请求中的自填用户名、密码和公司。开始导出时以该账号调用紫鸟自动化接口；本功能不再依赖 API Key、CLI profile 或开放平台终端绑定。

预览、任务和批次按账号 ID、公司、用户名生成的不透明身份摘要隔离。密码不写入预览、批次、任务上下文或日志；任务启动后固定凭据，不随页面切换账号改变。旧 CLI 批次不自动归属新账号，原始文件及汇总保留，需要使用平台账号重新导出。已有自动化客户端会复用，普通模式无法接入时明确提示退出普通模式后重试，不强制结束其他店铺；本批次固定一次打开一家店。每店完成或失败后关闭该店并确认浏览器端口已退出，才继续下一店；关闭失败或启动响应无法确认时暂停后续店铺。

0.2.60 取消勾选、刷新和预览步骤。用户每行填写一个完整店铺名及输出目录后，直接调用启动接口；后台使用固定的所选账号读取最新店铺并匹配，再创建批次。重复输入和空行自动忽略，保留输入顺序。只按紫鸟平台元数据识别 TEMU，不按国家关键词过滤。名称不存在、同名歧义或平台不符时不创建批次，直接显示原因；同名店铺需在紫鸟中改成不同名称。旧版预览接口保留兼容，当前页面不再依赖它。

TEMU 登录复用紫鸟保存的信息。遇到已观察到的地区页面时，点击中国地区商家中心；仅在精确的官方登录域名/路径中等待账号和密码自动填充，勾选登录确认并点击授权登录一次，之后返回业务标签页。脚本只返回是否填充的布尔值，不提取或记录账号、密码值。没有自动填充、遇到验证码或无法唯一确认控件时，明确提示人工处理，不绕过验证。

## 实测页面与完整性检查

商品列表地址来自真实页面导航：`https://agentseller.temu.com/goods/list`。打开精确匹配的紫鸟店铺，验证返回店铺身份和代理 IP，经店铺启动页初始化登录态后导航到商品列表，并固定 Selenium 窗口句柄。通过当前 DOM 解析唯一控件，使用 Selenium 元素点击；不调用推测的 TEMU 业务接口。导出选择、下载捕获、完整性检查及 Excel 合并逻辑保持原有规则。

识别 Beast Core 菜单的可见文字、版本化的活动页签样式和下拉控件。展开筛选，点击重置，只保留“在售中”，检查输入值、站点选择标签及快捷筛选状态。下载按钮数量需与活动页签数量一致，不能在查询尚未更新时下载。

页面顶部当前卖家名需唯一，且与紫鸟店铺名最后的 `-卖家名` 一致。两家实测分别匹配 `homasrapkA`、`herefn`。不满足此命名方式或存在多卖家歧义时明确失败，需要核对后适配，不能默认选第一个卖家。

页面异步出现“您有以下待办任务需要尽快处理”时，仅关闭已知标题所属弹窗，不点击“去处理”等业务按钮。等待关闭控件动画完成；若 Selenium 明确报告点击被遮挡、尚未发生，只在确认关闭该待办弹窗后重新解析控件并重试一次。未知遮挡、操作结果不确定和最终导出提交不自动重复。

下载弹窗需显示相同 SKC 数，勾选“全部商品信息”并确认必要字段齐全，然后只提交一次“导出”。记录本次页面生成 XLSX Blob 的原始字节并保存，不扫描历史下载目录。完成后恢复页面临时下载监听。

平台弹窗提示单次最多 40,000 条，超出仅导出前部分。程序对超过 40,000 个 SKC、文件达到 40,000 行、文件唯一 SKC 数与查询不符等情况判失败，保留原始文件供诊断。当前尚未实现超限分批下载，不能把截断结果记成成功。

## 数据与重试约定

- 第一列固定为一个“店铺名”，逐行使用紫鸟完整名称。其余列按字段名对齐，默认沿用需求中的 17 列，新字段追加并记录。
- 全部非空原始行均读取，包括隐藏行、已作废价格、零库存。只按在售中校验，不按申报价格状态筛选，不按 SPU/SKC/SKU 或跨店去重。
- 本次菲律宾原始文件还有 2 行“待卖家确认”，依照只筛在售中口径保留。
- 原始文件字节不修改；汇总将标识符转为文本以保留精度和前导零，价格与库存保留数值，标题保留原语言且不转成公式。
- 空字符串和空白单元格均视为空值；本次全部非空字段与源文件逐行对照一致。输出默认不隐藏行，不继承原文件筛选条件。
- 批次及每店每次尝试独立目录，原始文件和旧汇总不覆盖。`manifest.json` 原子保存状态、文件哈希、字段变化、卖家和查询数量证据。
- 单店失败继续其他店；认证失败停止后续业务调用。有失败时汇总标为“部分结果”；全部失败不生成冒充成功的空汇总。
- 重试只处理未完成或原始文件校验失败的店铺。有效成功文件保留，重新生成完整汇总，不向旧表追加。
- 只有活动在售页签明确为零且存在独立空结果提示，才记录无数据。全部确认为零时可生成仅表头结果；空下载不能替代页面证据。
- Windows 批次文件锁及应用任务锁阻止重复执行。应用重启可继续当前 profile 最近批次。
- 汇总单工作表上限 1,048,575 条数据行，超出明确失败。

## 已执行验证及边界

本次真实原始文件模板为 16 列，添加店铺名后为约定的 17 列，无新增或缺少业务字段。两店唯一 SKC 数与页签一致。泰国 7,751 行已生效、4,432 行已作废；菲律宾 1,934 行已生效、1,194 行已作废、2 行待卖家确认。零库存共 4,257 行，全部保留。逐行比较仅将空字符串和空单元格等价处理，其他字段均与源文件一致。

两店通过真实 AppBridge 和 TaskManager 执行生产导出方法，观察器只记录事件。首次两店批次中泰国成功、菲律宾被迟到的待办弹窗遮挡；修复后调用真实失败重试入口，只执行菲律宾，再重新汇总全部结果，未重复追加泰国数据。尚未以真实无数据店铺或所有登录状态被清除的店铺验收；对应异常分支由本地测试覆盖。

诊断中还出现过一次平台文件异常：页面查询 2,104 个在售 SKC，但导出中 1,000 个 SKC 的商品状态写为“未发布到站点”。程序按原有严格校验拒绝汇总并保留该文件；下一次下载恢复正常，未改写状态或跳过异常行。页面显示“导出成功”并不能替代文件内容校验。

下载接收已在这两家店的 Blob 导出验证。其他平台版本若使用下载中心、跨域下载或多文件拆分，当前会明确失败，需另行适配。单文件接收上限 128 MiB，默认导出等待 300 秒。没有自动添加国家、日期或申报价格条件规避上限。
