# TEMU发货渠道更改

该模块在马帮 ERP 的「物流 → 物流授权 → 平台物流」中搜索 TEMU，只将已开启（ON）的渠道按页面顺序对应 Excel 数据，逐条保存申报重量和包裹长宽高。已关闭（OFF）的渠道跳过，不占用 Excel 行。桌面入口为「马帮流程 → TEMU发货渠道更改」。

## 使用方法

1. 绑定并选择具有物流授权设置权限的马帮账号。
2. 选择每日随机长宽高 `.xlsx` 文件，点击「读取文件」查看数值与原始行号。
3. 点击「查询渠道并预览」，核对已开启渠道数量、渠道名称、Excel 行号、尺寸和重量。
4. 数据足够时点击「开始批量设置」。保存后会重新读取渠道设置并核验，页面逐行显示进度及结果。
5. 如果部分渠道失败，使用「继续未完成渠道」。继续任务使用之前保存的数值和对应关系，不重新分配 Excel 行。

运行日志及结果表逐渠道显示长、宽、高和重量的「原值 → 目标值」，并单独显示实际读回值。原值取自执行时首次读取的渠道设置，重试和恢复任务时保留；保存后只有实际读回符合目标才显示已核验。当前值已经相同的渠道显示「无需修改」，汇总分别统计「已修改」和「无需修改」，整批均相同时明确提示未提交任何修改。旧任务未记录的实际值不会用目标值补齐。

开发环境可直接启动本页：

```powershell
.\.venv\Scripts\python.exe desktop_entry.py --page=temu-shipping-channel
```

## Excel 与匹配规则

- 支持 `.xlsx`，优先读取 `Sheet1`；前十行中必须有唯一的长、宽、高、重量表头。尺寸单位为 cm，重量单位为 g。
- 跳过表头，保留所有数据行的原顺序及重复尺寸。数据区域中间的空行、缺失值、非正数和公式错误会阻止导入，避免后续渠道错位。
- 重量按四舍五入保留两位小数，舍入后须大于零；不再限制申报重量上限（原先「必须小于 500 g」的校验已取消）。上限以马帮渠道表单和 TEMU 渠道自身的申报规则为准，本模块不预先拦截。
- 读取文件中已经保存的公式计算结果，不限制文件或 `TODAY()` 缓存日期，不需要为了跨天导入而重新计算保存。日期配置缺失、不同或无法识别也不会阻止导入；仅当长、宽、高、重量本身缺少有效数值或公式缓存时，才需要补全或用 Excel/WPS 计算并保存。
- 预览时固定本次数据及「渠道标识 → Excel 行号」关系。任务跨天或程序重启后继续使用这份记录，不读取新的日期公式值。
- 仅处理开关为 ON 且已有「设置」入口的渠道。OFF 渠道直接跳过，不修改、不启用、不占用 Excel 行；关闭渠道之间的已开启渠道连续对应 Excel 数据。查询完整性或开启状态无法确认时停止，避免遗漏。
- 只按已开启渠道数检查 Excel 是否足够；不足时整批不可执行，不会循环使用数据或只提交前若干条。多出的 Excel 行不会分配给渠道。
- 预览之后的渠道顺序变化不会改变已保存映射；已开启的可设置渠道集合发生变化时，必须重新预览。
- 旧版本未按开关筛选的预览或执行记录不能继续，需重新查询预览，按已开启渠道重建对应关系。

## 保存与恢复

修改字段为申报长、宽、高、重量，以及文档截图中启用的「自动填写包裹尺寸」「优先按渠道申报重量进行申报」「优先按渠道固定体积进行申报」。

网关读取完整表单，恢复接口单独返回的店铺仓库选择，并重建网页保存时追加的标签、地址等字段。每条提交前重新查询渠道当前开关状态；任务运行中被关闭或已不存在的渠道不会提交修改。其他配置随原值保留。保存后同时核验目标字段及其余配置；仅收到成功响应不足以判定成功。

任务记录保存在本机应用数据目录下的 `temu_shipping` 文件夹。提交前先保存当前行状态，避免程序中断后无法判断该行是否提交。遇到超时，先读回检查实际值；失败后的重试沿用原行数据。已经核验成功的渠道不会重复提交。重试时发现其他配置发生变化，会停止该行并要求重新核对。

同一账号的执行受进程内锁及操作系统文件锁保护。密码只用于登录，不写入执行记录、源码或任务日志；执行记录只保存账号摘要、渠道标识、目标数据及核验信息。

从 0.2.54 起，同一进度目录的读取、最新进度查询和保存共用可重入锁，避免界面轮询的文件句柄与 Windows 原子替换冲突。外部程序短暂占用文件时，替换最多尝试 6 次，总等待 1.55 秒；持续失败则暂停任务，不再提交后续渠道，保留原进度。恢复时沿用原对应关系，先读取实际设置，已提交并符合目标的渠道不重复提交。

## 实现位置

- `backend/services/temu_shipping_workbook.py`：Excel 只读校验及数值固定。
- `backend/services/temu_shipping_gateway.py`：马帮会话、列表查询、完整表单解析、提交及核验辅助。
- `backend/services/temu_shipping_channel.py`：顺序映射、任务记录、并发互斥和失败恢复。
- `backend/app_bridge.py`：文件选择、读取、预览、执行和进度恢复接口。
- `frontend/pages/temu-shipping-channel.html` 及对应 JS/CSS：导入、预览、执行、分页和日志。

## 验证情况

2026-09-10 初次真实页面只读联调统计的 99 条为包含 OFF 渠道的全部已有设置入口，不能作为本模块的待设置数量；原先「80 组数据缺少 19 组」的结论已撤回。按修正规则重新在线只读查询，最新结果为 67 条 ON、32 条 OFF。80 组 Excel 数据足以对应 67 条已开启渠道，连续匹配 Excel 第 2～68 行，剩余 13 组不使用；预览已确认可执行。渠道状态会变化，实际执行数量以当次预览为准。线上渠道没有被修改。

在真实浏览器加载首条渠道表单，执行网页原有保存逻辑，并通过 JavaScript 捕获及网络路由中止两层机制拦截保存。比较模块与网页生成的 202 个最终字段：非管理字段全部相同；申报重量的 `500.00` 与 `500` 为等价数值格式。此检查验证了请求构建，没有发送真实保存请求。

第 1、50、99 条渠道的真实读取响应通过离线解析检查。分别验证完整仓库映射、原配置保留及目标字段替换。自动化测试覆盖顺序、重复尺寸、日期缓存、精度、数据不足、超时读回、重启恢复、账号隔离、并发、损坏记录、界面异步响应和已有页面回归。1440 与 980 像素宽窗口完成视觉检查。

真实写入后的服务器行为尚未实测。重新查询已开启渠道并确认 Excel 数据足够后，可通过本模块执行完整批次并核验线上结果。
