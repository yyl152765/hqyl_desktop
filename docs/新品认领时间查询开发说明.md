# 新品认领时间查询

入口为工作台或侧栏「BigSeller → Shopee 商品 → 新品认领时间查询」。用户选择 `.xlsx`、工作表、站点和输出目录后，使用设置中选中的 BigSeller 账号查询，完成后另存结果文件。

## 查询口径

- 第一版范围为当前账号可见的 **Shopee 在售商品**，默认全部站点，也可选择单一站点。它不代表已下架、已删除商品或不可见店铺的历史最早上架记录。
- 按主 SKU 精确搜索：`searchType=parentSku`、`inquireType=2`；保留完整 SKU，不裁剪子 SKU 后缀。对返回的 `itemSku` 再核对。
- 请求按 `create_time` 升序，并读取完整分页后比较 `createTimeStr`。同一主 SKU 的重复源行仅查询一次。分页缺漏、重复页、创建时间缺失或格式异常会记为查询失败，不能当作未匹配或改取另一个商品。
- 取创建时间最早的商品，从**同一条记录**读取 `shopName`、`itemId`、`createTimeStr`、`platformCreateTime`。显示创建时间并列时，若并列组的 `createTime` 毫秒时间戳均有效，继续按原始时间戳比较；最终并列才按 Item ID 升序稳定选取。原始时间戳缺失或异常时仅按 BS 显示时间精度处理并列，并在说明中标明。导出保留 BS 显示时间，不自行补入未核对的时区或秒数。
- **BS上架时间按 BS 的“平台创建时间” `platformCreateTime` 展示**。不使用定时发布页的 `publishTime` / `timingTimeStr`。平台时间缺失时留空并说明，绝不拿 BS 创建时间代替。
- 单站点查询按每条商品的 `site` 字段过滤；缺少站点时不能证明所属范围，会明确失败。

字段依据为 [BS 官方 Shopee 页面脚本](https://cdn.bigseller.pro/bs-web/2026-08/60675.chunk.98ddce.js)。2026-09-30 开发时已核对脚本，并通过真实商品接口验证 `itemSku`、`shopName`、`createTimeStr` 和 `platformCreateTime` 字段。后续使用原表小样本完成桌面桥接的真实导入、登录、查询和导出：8 行包含 12 个不同 SKU，其中 5 个匹配、7 个在当前范围内未匹配、0 个查询失败。尚未执行完整文件的全部 SKU 查询，也未完成 BS 网页逐项对照。

登录诊断中曾遇到验证码识别服务 `api.ttshitu.com/predict` 返回 HTTP 500，当时尚未提交 BS 登录请求。随后使用相同账号和原始请求参数重试，识别接口返回 200、BS 登录成功，且实际商品查询成功；验证码服务的账户查询也成功。现有证据更符合识别接口的临时异常，但未保留此前 500 的响应正文，不能确定服务端的具体根因，也不能据此认定账号密码有误。

## Excel 处理

- 识别 SKU、主SKU、Parent SKU、库存SKU、库存SKU编号等表头。跳过空行、明确的物流批次标题；无法处理的单元格保留原因，不静默当成正确 SKU。
- 同格多行 SKU 分开查询，回填时各项带 SKU 对齐，明细页逐项列出。数值 SKU 的前导零按源单元格格式保留。
- 保留源文件，导出唯一文件名的新 `.xlsx`。原有「上架店铺」「上架时间」及其他工作表不覆盖。
- 新增「BS最早创建店铺」「BS创建时间」「BS上架时间」「BS查询状态」「BS查询说明」和查询明细。单 SKU 时间写入真正的 Excel 日期值。
- 只更新本模块标记的生成列，用户自己建立的同名列仍保留。重新查询已导出的文件不会重复堆叠模块自己的结果列。
- 单次最多 10,000 个不同 SKU。用户提供样本的主表解析为 8,930 个有效数据行、8,873 个不同 SKU，包含两行多 SKU 单元格、499 条批次标题和一条分组说明。

## 失败与恢复

请求沿用原有节流、网络重试和服务端冷却时间。每项结果保存到输出目录的「BigSeller认领进度」SQLite 文件。再次选择进度文件时校验账号、源文件哈希、工作表、站点和查询口径，仅补查未完成项。

查询失败与确认未匹配分别标记。遇到登录、权限或持续限流时保留已经确认的结果。Excel 导出失败时仍可从已保存的进度重新导出。进度文件不保存密码、Cookie 或验证码服务凭据。
