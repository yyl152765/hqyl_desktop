# 0.2.77 发布说明

日期：2026-10-20。

修复 Lazada 提现统计中“菲律宾165”“菲律宾4”等简称无法匹配带负责人、LZ 前缀、补零店号及仓码后缀的紫鸟完整店铺名称的问题。

## 变更

- 支持“菲律宾＋店号”“马来/马来西亚＋店号”“泰国＋店号”，兼容繁体国家名、全角数字和前导零。
- 只识别紧跟国家名的完整店铺编号。`菲律宾4` 可匹配 `菲律宾004`，不能匹配 `菲律宾024`、`菲律宾040`、`菲律宾0040` 或 `菲律宾4A`；内部 `PH004` 仓码不能替代店铺编号。
- 按 Lazada 平台、国家和唯一候选选择店铺；有多个同国家同号店铺时列出完整候选，要求填写完整名称，不根据输入顺序或已经选择的店铺暗自排除歧义。
- 简称与完整名称指向同一店铺时，仅排程一次，并明确提示重复输入。当前选择国家与店铺国家不符时停止该项。
- 结果保留用户输入简称，区分 `ambiguous`、`not_found`、`duplicate`、`country_mismatch`，并保留候选完整名称。
- 桌面和共享本地 runner 继续共用同一匹配实现。保留 0.2.76 的钉钉本地配置读取、操作人选择、启动前检查、收入账单下载兜底及国家归档目录。

## 使用与验证范围

可以继续逐行填写原来的“菲律宾165”等简称。遇到多个候选时，改用日志或结果中列出的紫鸟完整名称；当前绑定紫鸟账号没有授权或不存在的店铺仍会提示未找到。

本轮使用用户的 11 个输入格式作离线回归，验证匹配逻辑及结果归属；未打开真实店铺、未运行采集或生产上传。本次日志返回的 799 条当前浏览器目录未重新读取：可用 CLI 与客户端账号不一致，未自动切换账号。历史 810 店快照只用于结构和歧义参考，不作为当前匹配结果或当前授权证明。

之前的真实钉盘只读认证与收入页空态证据均为历史验证，不代表本次已在报错电脑完成实店验收。
